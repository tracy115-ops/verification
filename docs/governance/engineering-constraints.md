# 企业工程约束

状态：项目约束生效；具体工具配置在代码骨架阶段落实。适用于后续新增、修改与重构，不能把“企业级”理解为引入大量基础设施。

## 代码规模与职责

- 单个受维护源码文件最多 **2,000 个物理行**，包含空行与注释；单个函数、方法、构造函数、匿名回调最多 **200 个物理行**，从声明开始到函数体结束计数。
- 目标为文件少于 800 行、函数少于 80 行；文件达到 1,500 行、函数达到 150 行时主动评估拆分。目标不是允许把每个文件写到上限。
- 测试、迁移脚本和手写配置代码同样不能堆砌。生成代码、第三方文件只可在明确列出的目录豁免，必须标注生成来源；不得将手写逻辑伪装成生成物。
- 禁止以压缩排版、超长单行、拆成无意义转发函数绕过检查。按业务责任拆分，避免“万能 Service”、巨型 store 和通用工具杂物箱。
- 后续 CI 使用物理行检查及解析语法树的函数跨度检查；未配置检查器前逐文件人工核对，不能声称已有自动门禁。存量超限先拆分所触及模块。

## 国际化从第一天开始

| 对象 | 约束 |
| --- | --- |
| UI、错误、通知、导出报告 | `zh-CN` / `en-US` 同步维护；使用语义消息 key 与参数，不拼接翻译片段 |
| 状态和 API | 使用稳定代码，例如 `run.cancelled`、`verdict.inconclusive`，展示层负责翻译 |
| 时间、数字、单位 | UTC 存储，按用户时区、locale 格式化；使用复数与插值规则 |
| 用户 Spec 和脚本 | 保留原文、编码和版本；翻译是独立派生产物，不更改原文锚点 |
| Agent 输出 | 结构字段名固定；`contentLocale` 指定内容语言，`uiLocale` 不强制重写已有产物 |
| 测试 | 检查消息 key 对齐、缺失回退、长文本、中文文件路径及切换语言后状态稳定 |

建议使用 React 国际化库承载 ICU 消息，后端返回 `code + messageKey + params`。用户内容与界面翻译分开，避免把需求 ID、路径或协议字段翻译掉。详细库版本在落地时核实和锁定。

## 架构与扩展

- Command / IPC 只做校验、授权与转发；Service 组织用例；领域模型表达业务规则；Repository 负责数据访问，SQL 不进入 UI 或编排逻辑。
- 领域层不依赖 Tauri、CLI 协议或 SSH。外部能力通过 `AgentDriver`、`ExecutionTarget`、`DocumentImporter`、`VerdictEvaluator` 等接口注入。
- 模块公共接口显式导出；跨模块不能直接修改对方表。通过应用服务协作，避免循环依赖与到处判断 Provider 名称。
- 外部 JSON、文件及 Agent 产物都必须进行结构与业务约束校验。Schema、工作流、模板、提示词和产物均版本化。
- TypeScript 启用 strict，外部输入用 `unknown` 收窄；Rust 使用类型化错误，禁止以 `unwrap` 处理可预见运行故障。核心规则优先纯函数。

## 可维护性与运行质量

- 所有长任务有 deadline、取消、进度、明确终态和资源回收；阻塞任务不得卡住 UI 或异步执行器。
- 并发、日志容量、上下文、重试和费用预算有上限。拿不到费用数据时显示未知，不以零代替。
- 保留运行快照、证据 hash、关联 ID、操作主体与审批记录；诊断信息应可脱敏导出。
- 需求变更、代码变更、模板更新使相关确认失效；不能沿用旧绿灯或旧执行授权。
- 单测覆盖规则和状态转换，契约测试覆盖适配器，集成测试覆盖数据库及进程生命周期。修复必须证明失败路径和回归路径。
- CI 计划包括格式、lint、类型、行数、单测、国际化 key、契约与依赖边界；覆盖率门槛在建立基线后确定，不能用无意义测试凑数字。

## 配置与 Git

凭据存于系统凭据库或受控环境注入；Git 中仅保存引用和无密钥示例。运行数据与工作流定义分离，工作流导出默认脱敏。本地 SQLite 数据库不能直接作为跨机器共享文件。

提交使用 `docs:`、`feat:`、`fix:`、`refactor:`、`test:` 等前缀。PR 描述说明行为、验证结果及迁移影响；涉及 UI 提供截图，协议变更附兼容策略，架构变更补充 ADR。

本文件与根目录 `AGENTS.md` 是本项目约束入口。既有技能中的更小函数建议作为目标；不得放宽本项目 2,000 / 200 的硬上限。
