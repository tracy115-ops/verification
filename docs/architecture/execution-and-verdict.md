# 测试执行、判定分析与结果动作

状态：设计提案。执行目标、测试结论与后续动作分别建模，避免 Agent 从日志推测出一个绿灯后直接修改产品代码。

## 测试开发模式

| 模式 | 输入与行为 | 验收条件 |
| --- | --- | --- |
| Agent 自实现 | 已确认用例、项目测试约定、允许的依赖、目标环境 | 每条用例有实现或明确不支持原因，断言与预期一致 |
| 用户模板生成 | 上述输入 + 固定版本模板及 manifest | 保留 fixture、命名、入口和报告协议；校验必填参数 |

模板 manifest 应包含 `id/version/framework/runtime/files/parameters/entrypoint/resultParser/requiredCapabilities`。模板视作可执行输入进行评审，不因名为模板就直接信任；不在字符串里拼接未经转义的参数。

开发在独立工作区中生成变更，展示文件 diff、依赖变化和用例→断言映射。用户手工修改与 Agent 修改有各自 revision；重生成先合并或展示冲突，禁止静默覆盖。模板版本更新不自动改动历史脚本。

首个参考框架建议 pytest + JUnit XML，但最终通过框架适配器支持 Playwright、自定义脚本等。业务用例可以是手工测试：无法自动执行时明确标记 manual / blocked，不生成空脚本假装实现。

## 统一执行契约

`ExecutionTarget` 提供 `probe / prepareWorkspace / transfer / execute / query / cancel / collect / cleanup`。运行请求包含 attempt ID、运行清单 hash、argv、cwd、受控环境引用、deadline、资源限制、证据路径和清理策略。

预检确认：OS / 架构、解释器 / 测试框架、依赖、目标服务可达性、目录读写、磁盘、凭据可用性、测试数据与资源配额。环境不可用进入 BLOCKED，不作为产品缺陷。

执行计划绑定输入 / 脚本 hash、代码 commit 或工作树快照、目标 Profile 修订、实际目标身份、命令与预算。SSH 固定 host key，WSL 固定发行版身份；若身份改变，重新预检和确认。Agent 不能在批准后替换目标或脚本再沿用旧授权。

## 三种执行环境

| 环境 | 实现建议 | 特殊问题 |
| --- | --- | --- |
| 本地 | 受管进程、明确 argv / cwd / env；Windows Job Object，Unix 进程组 | 中文 / 空格路径、退出码、子进程清理；不能只杀父进程 |
| SSH | 本机 OpenSSH / SFTP 传输运行包，远端固定入口读取 JSON manifest | host key、远端 shell 引号、断线后任务是否仍在、证据回收 |
| WSL | `wsl.exe --distribution <name> --exec <program> ...` 候选方式，按 Windows 版本实测 | Linux PATH、Windows / Linux 路径映射、文件权限与换行、发行版内清理 |

SSH 不能被当作天然 argv 透传；远程通常仍经 shell。建议传送运行 manifest 和测试包，由受控远端脚本读取，而非把 Spec、密钥或整串命令拼进 `ssh host '...'`。远端入口需要部署 / 验证，并使用唯一运行目录。

WSL 不简单把 `C:\...` 字符串替换为 `/mnt/c/...`。目录通过能力探测和可靠路径转换建立映射；可选复制到发行版文件系统再执行。杀死 `wsl.exe` 不证明 Linux 进程已停止，应使用发行版内任务 ID / 进程组确认。

每个 attempt 使用独立目录、传输 manifest、hash 清单和运行状态文件。先将证据写入临时区域，完成后提交 manifest；只读入声明的产物，校验路径不能逃逸（包括符号链接）和文件大小。缺失、截断、hash 不符应标记证据不完整。

## 取消、断线与副作用

运行状态至少区分 running、cancelling、cancelled、timed_out、connection_lost、unknown。请求取消成功不等于已停止；记录远端确认和清理结果。SSH 断线后通过 task ID 查询状态，查不到时保留未知，不把连接错误自动归类断言失败。

有副作用的测试需要环境标记、数据命名空间、资源互斥和清理 / 补偿方案。重试只在确认可重复或已隔离时启动。删除远端运行目录必须确认对应 run 和根目录，保留失败证据到配置的保留期后再清理。

## 判定规则与分析 Agent

先由结果解析器和确定性规则得出用例级结论，再交分析 Agent 解释原因、引用证据、建议补测。分析 Agent 不能把失败断言改判为通过，也不能以主观 confidence 替代断言。

| 状态 | 条件 | 后续方向 |
| --- | --- | --- |
| PASS | 已确认用例的必需断言全部完成并满足；证据和版本一致 | 归档与汇总覆盖 |
| FAIL | 有完整证据支持的业务断言不满足 | 产品 / 用例问题分析，生成缺陷草稿 |
| ERROR | 测试框架、执行器或脚本异常，无法正常完成 | 诊断基础设施或测试实现 |
| BLOCKED | 依赖、环境、权限或需求歧义阻止验证 | 请求补充条件或澄清 |
| INCONCLUSIVE | 缺证据、语义冲突、未知执行状态，无法可靠判断 | 补证据、人工复核 |
| NOT_RUN / SKIPPED | 未执行或不满足显式适用条件 | 展示原因；不计为 PASS |

一个退出码 0 的脚本如果没有必需断言或未产出报告，应为 INCONCLUSIVE / ERROR，具体由解析契约解释。用例不存在明确 oracle 时采用人工确认或待澄清，不让同一个 Agent 同时发明预期并宣布正确。

判定产物包括 `scope/inputDigest/evaluatorVersion/result/checks/evidenceRefs/uncertainties/recommendations`。证据引用校验真实存在且属于本轮；原始证据保留，展示内容脱敏。日志、Spec 和远端输出均是数据，不能作为提升工具权限的指令。

## 整体结果与发布判断

展示结果向量：业务失败数、执行错误数、未知数、覆盖缺口数、跳过数与通过数。任何已知 FAIL 必须可见；存在未知 / 错误不能因为其余用例 PASS 而隐藏。

`releaseReadiness` 单独计算：必需需求有确认覆盖、用例已实现、所有必需检查在当前快照 PASS、没有未解决的 BLOCKED / ERROR / INCONCLUSIVE，且排除项符合已确认规则，才允许 ready。范围内全跳过、零用例或零断言不算 ready；历史通过不替代本轮条件。

## 判定结果后的 Agent 行为

这里把用户提出的“最后判断结果后的行为”解释为可配置策略和可审计的动作计划，而不是自由运行的下一个聊天 Agent。

| 触发 | 默认动作 | 可配置升级 |
| --- | --- | --- |
| PASS 且范围完成 | 生成报告、保存基线 | 经授权写入外部报告系统 |
| 场景 / 覆盖缺口 | 生成补充场景与用例候选 | 用户确认后派生补测 run |
| FAIL | 生成根因候选、最小复现、缺陷草稿 | 经授权创建外部缺陷 |
| ERROR | 生成环境诊断与可重复操作建议 | 满足条件时有限基础设施重试 |
| INCONCLUSIVE | 列出缺失证据与可执行收集计划 | 请求人工判定或补证据 |
| 允许自动修复 | 独立 worktree 生成修复 diff 和回归建议 | 审核后运行修复验证；合并 / 部署仍是独立动作 |

动作链为 `AnalysisProposal → PolicyDecision → ActionPlan → AuthorizedExecution → AuditEvent`。默认本地生成草稿和归档；涉及外部写入、产品代码修改、合并或部署按明确项目策略和本次授权执行。审批固定动作内容摘要；外部系统写入采用幂等键并记录返回 ID。

修复策略固定最大迭代、时间 / 费用预算和停止条件。同类失败重复出现或证据不足时停在待处理，不能无限修改测试断言直至变绿。自动修复不得擅自修改验收标准、弱化断言或删除失败用例。
