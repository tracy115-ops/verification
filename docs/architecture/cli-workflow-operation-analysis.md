# CLI 操作与工作流接入分析

更新：2026-10-28。本文件区分当前实现、已经验证的能力与待确认方案；设计背景见[CLI 与 Provider](cli-and-provider-design.md)，操作步骤见[本地 Python 工作流](../workflows/local-python-verification.md)。

## 用户操作与职责

设置页负责发现本机 CLI、选择原生配置与模型，以及配置测试框架和目标。编排页保存节点、依赖与角色绑定。会话页选择已保存的版本、输入题目并驱动流程；进度、人工确认和产物留在应用内。局域网服务只负责共享场景、因子、分工和评审，不代替成员启动 CLI 或执行测试。

流程状态和产物由应用保存，CLI 是单次节点任务的执行器。节点间传递经结构与引用检查的产物，而不是依赖某个 CLI 的私有会话。普通对话当前采用上下文重放；原生会话恢复尚未实现。

## 当前驱动边界

| CLI | 配置与启动 | 验证状态 |
| --- | --- | --- |
| CodeAgent | 内部模型，不传 `--model`；扫描路径或 `CODEAGENT_CLI_PATH`。调用前检查 `--help` 是否支持所需非交互与工具控制参数。 | 用户提供交互命令 `codeagent --dangerously-skip-permissions`；本机未安装，自动调用、事件格式及权限控制必须在目标环境实测。 |
| Codex | native 登录，显式模型；`exec --json`，提示通过 stdin，限制工具与工作区。 | 本机真实推理与独立黑盒脚本生成已验证；不同版本仍须回归。 |
| Claude | native 登录，显式模型；非交互 stream-json，限制工具 / MCP。 | 协议夹具覆盖解析；实际账号及目标版本需验证。 |
| Pi | native 登录，显式模型；JSON 模式并关闭工具 / 扩展等入口。 | 协议夹具覆盖解析；实际账号及目标版本需验证。 |

扫描版本不代表登录、模型可用或非交互协议兼容。自定义 Provider 表单目前只保存配置，运行时未实现通用凭据注入与连接；不能把其展示为已连通。实际参数与终态处理以 `crates/agent-runtime/src/conversation.rs`、`codeagent.rs` 和协议实现为准。

## 一次流程如何调用 CLI

1. 创建运行时冻结已保存流程、节点绑定、题目、Agent Profile 和可选框架配置；逐节点解析输入。
2. 需求、场景、用例、脚本、分析分别使用对应角色 Profile 发起独立 CLI 任务。提示词包含原文、当前输入和输出 Schema；用户内容作为数据处理。
3. 进程事件归一化，只有明确的协议终态、成功退出和有效产物同时满足时才推进。系统检查原文引用、场景 / 用例 ID、脚本方法映射和判定引用。
4. 需求、覆盖、用例及执行计划分别停下人工确认。执行计划包括目标、框架、脚本和摘要；预检不导入框架或访问目标。
5. 用户确认后由本地执行器运行 Python，收集真实接口证据。判定 Agent 只能引用失败断言；执行异常与缺证据保持无法判定。后续动作当前仅生成报告。

每次调用受超时、输出限额、取消与进程树清理约束。执行具有副作用，因此执行中断后不自动重试；确认内容或上游产物改变后授权失效。CLI 权限参数和 Python AST 校验均不等于操作系统沙箱。

## CodeAgent 目标环境验收

在安装环境记录版本和脱敏 `codeagent --help`，确认非交互输入、结构化输出、终态、工具 / MCP 关闭及取消行为；再用无敏感信息的小型结构化任务验证成功、错误、超时和取消。最后用真实框架及测试目标进行人工确认后的闭环试验。不得只凭交互启动成功推断协议兼容，也不要求用户另配模型。

## 后续设计决策

- 为 CLI 版本维护能力矩阵和可重复契约测试，区分已发现、可调用及角色认证。
- 增加产物编辑、退回与重新确认，并使相关下游产物失效；目前不能假定已有此能力。
- 扩展多文件框架、pytest、SSH / WSL 和执行隔离；先明确依赖、证据格式、取消与远端状态对账，再接入执行器。
- 工作流生成 Agent 输出受版本化 Schema 校验的草稿，由用户审核保存；当前流程编辑器不等于已实现自动生成。
