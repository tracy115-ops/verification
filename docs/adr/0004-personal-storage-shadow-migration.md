# ADR 0004：个人数据先做 SQLite 影子副本，再切换主仓库

状态：阶段一实施；主仓库迁移尚未启用。日期：2026-11-08。

## 问题与决策

会话、流程和框架在 localStorage，公开 CLI 记录在 IndexedDB。直接替换读写路径会把迁移、业务变更和数据恢复同时引入，失败时难以定位。先建立独立、可校验的副本，日常读写保持原路径。

设置 → 数据管理提供手动创建、重新校验、导出副本。活动任务或未保存的流程更改会禁止创建；采集结束时再次比较来源键，变化则拒绝写入。采集复用个人备份的业务校验；不复制浏览器登录令牌或 CLI 认证文件。副本可能包含用户文档、脚本和本机配置路径，属于本机个人数据，不上传协作服务器。当前没有加密或跨设备容灾能力。

## 阶段一协议

- 应用本地数据目录固定文件 `personal-shadow-v1.sqlite3`；不接受调用方提供路径。
- Schema `user_version=1`。`snapshots(id, payload, sha256)` 保存现有备份格式的精确 UTF-8 字节；每份最多 20 MiB，保留两份，文件超过 128 MiB 停止写入。
- 使用 bundled SQLite，避免依赖用户安装数据库。写入采用 `BEGIN IMMEDIATE`、完整同步；校验旧副本、插入新副本、删除过期副本与校验新副本在同一事务中完成，失败回滚。[rusqlite 事务接口](https://docs.rs/rusqlite/0.41.1/rusqlite/struct.Transaction.html)
- 创建时前端校验业务 Schema；原生边界独立限制封装、大小和存储键。读取/导出检查 SQLite `quick_check`、SHA-256 和封装；创建、导出时前端再验证摘要，导出还要重新校验备份业务结构。状态页的成功仅报告存储完整性，不认证未来版本的业务兼容性。
- 不兼容版本、数据库损坏或摘要不匹配会保留文件并拒绝写入。状态查询不创建空文件。日志只记成功/失败，不记录 payload、路径、需求或凭据。
- 导出在同一只读事务中检查并读取指定快照。已轮换的快照返回稳定错误。导出的 JSON 可通过原有导入入口预校验、确认后恢复；没有自动恢复或主仓库切换。

## 下一阶段与退出门槛

阶段二再引入类型化会话/运行/事件表，原文、脚本和证据按摘要独立文件索引。采用仓库接口适配浏览器和原生实现；影子双写/对比不能代替主读切换验收。

主读切换前必须验证：升级前完整备份、迁移标记和可重入恢复、磁盘满、进程强杀、跨存储来源一致性、迁移失败回退、容量与性能。当前采集不是跨 localStorage/IndexedDB 的原子事务，依赖停止任务并检查来源变化；两份副本共用一个数据库文件，不能称为独立容灾备份。数据库禁止放在 SMB/SSH 共享目录，多人协作仍由中心服务持有项目存储。

## 验证范围

Rust 测试覆盖重开读取、字节一致、两份轮换、事务失败回滚、摘要篡改、损坏文件、未知版本、非法输入和导出。前端契约覆盖来源变化和原生摘要不匹配，界面回归覆盖创建、刷新、导出及失败后清除旧成功状态。实际断电、强杀和物理磁盘满尚需单独故障注入验收，不由事务回滚单测替代。
