# ADR 0005：桌面会话按来源显式迁入 SQLite 主存储

状态：0.15.0 本地实现与验收通过，准备发布。承接 ADR 0004 的影子保护，不替代已有副本。

## 范围

首批迁移会话、会话输入草稿、运行快照及内嵌产物。流程库、全局配置仍在 localStorage，CLI 公开记录仍在 IndexedDB；人工表单草稿仍为窗口内状态。不能称为全部个人数据事务化或完整跨存储原子备份。

设置 → 数据管理 → 会话事务存储，先检查并展示来源，再确认启用。新库初始化前必须成功创建当前个人数据的保护副本，并在异步步骤之间检查来源及操作归属未变。已有库只允许连接，不把旧浏览器数据覆盖到已有库。浏览器来源保留原样，不双写；启用标记保存来源选择，之后的桌面启动在挂载工作台前读取并校验数据库。标记丢失时可从设置重新连接已有库。

## 提交契约

固定应用数据目录下 `personal-conversations-v1.sqlite3`，Schema 1：`sessions` 按稳定 ID、顺序、原始 JSON payload 和 SHA-256 保存每个会话，`metadata` 保存提交版本、数量与全量摘要。保留 JSON 字段顺序和字面量，避免改变已有评审摘要。事务内检查旧数据、比较预期版本、替换会话行和更新元数据；提交成功才提高 UI 的已提交版本。使用 WAL、完整同步和有限锁等待，不接受调用者指定数据库路径。

UI 通过仓库缓存同步读取，后台串行提交并合并尚未提交的快照。失败时保留最新内存内容、显示全局告警，阻止后续新的 Agent 任务；仍可取消已有任务。重试保持原预期版本，不对其他实例的新数据自动重放。可导出含未提交会话的恢复副本，该副本不代表数据库已保存成功。普通导出、影子副本、恢复及正常关闭先等待会话提交。

损坏、未知 Schema、校验失败或已启用库丢失时停止启动工作台，不自动使用空数据或旧浏览器数据。恢复页可重试，或显式确认打开可能过期的旧浏览器副本；该切换不覆盖 SQLite。切回之后重新连接已有库仍须保护当前来源并确认。

## 边界与验证

保留现有 50 会话及 200 万字符业务限制，不以使用 SQLite 宣称容量问题全部解决。多个实例采用乐观版本检查，不提供自动合并或跨设备数据库共享。恢复操作涉及多个存储，仍有既有回滚边界，不能视为单个跨 SQLite/IndexedDB/localStorage 事务。

验收包含迁移保护失败、来源变更、离页、已有库连接、版本冲突、保存失败恢复、读损坏拒绝覆盖、真实子进程强杀未提交事务、界面导出/清空/恢复、隔离命名空间中的原生重启。事务中断测试不能替代物理断电或真实磁盘满验收。
