# ADR-0003：增量建议与版本绑定的脚本覆盖

状态：采纳，2026-10-28。

## 背景

多个 Agent 和成员需要持续补充不完整的测试设计。整体替换分析会覆盖他人工作；一个“已覆盖”布尔值又无法区分人工声明、真实方法关联和执行结果。

## 决策

沿用 HTTP 命令、SQLite 事务及项目历史快照，新增可选的版本 1 协作扩展。建议记录来源、基线、原条目和逐条决策；服务从历史修订读取基线，不信任上传者伪造的原内容。合入前比较目标，无关条目变化允许继续，目标变化则拒绝。现有人工表单仍可编辑草稿，设计和用例独立评审。

覆盖声明、脚本方法映射、执行结果分开建模。用例修订号递增使关联映射及声明失效；关联场景和因子变更同样传播失效。脚本原文与 SHA-256 不可变，同名新版本参与当前覆盖，旧版本保留审计。共享执行结果属于成员导入的数据，必须匹配脚本摘要和方法，并明确显示来源；个人工作流只读取与本次计划摘要匹配的证据。

Python 方法核对采用固定 AST 解析程序，上传源码仅作为输入数据。拒绝空方法、缺失方法及超限源码，不运行测试或导入待测代码。宿主需要 Python，缺少环境时允许人工声明但不能宣称已核对。限制并发、输入输出及超时，错误返回稳定代码。

个人任务通过可审阅的补充包、脚本包交接，导出不携带 Provider 或执行框架配置。没有开放浏览器远程执行本机 Agent 或测试的权限。

## 取舍

不使用文本实时协同或自动语义合并；以修订冲突、逐条比较和成员决策维护基线。重复名称只作提醒，不能以不可靠相似度自动丢弃场景。AST 方法存在也不能证明断言充分，执行状态必须独立。

项目 JSON 仍受原体积限制，历史保留而不静默裁剪。未来更大团队可将协作实体拆表，但应保持命令、来源和版本语义兼容。
