# ADR-0001：本地优先的模块化单体

- 日期：2026-10-27
- 状态：Proposed（完成技术探针与产品评审后转 Accepted）
- 约束：本机 CLI 驱动、Provider 快速配置、可保存自定义流程、需求追溯、三种执行目标与企业工程规范。

## 决策建议

首发采用桌面工作台，建议 Tauri 2 + React / TypeScript + Rust，SQLite 保存业务状态，本地文件仓库存产物。领域核心按模块和端口隔离，持久化状态机负责工作流。Agent 通过已安装 CLI 子进程运行，直接 API Agent 循环不是首期必需项。

## 原因

用户的主要资源位于本机，图形界面有利于原文映射和用例评审。CLI、Provider、执行环境各有差异，需要稳定接口；业务流程和恢复状态应由产品自己掌握，不依赖对话历史。首期负载与团队规模尚未明确，模块化单体更容易验证端到端行为。

## 替代方案

| 方案 | 暂不选的原因 | 重新考虑的条件 |
| --- | --- | --- |
| Electron 全 TypeScript | Rust 核心更符合当前技能约定，但双语言成本需证实 | 团队以 TS 为主，进程及桌面验证显示 Electron 更易维护 |
| Web + 中心服务 + Runner | 首期需额外建设连接、部署与身份体系 | 多人协作、统一调度和集中审计是首发硬要求 |
| 通用分布式工作流引擎 | 本地单用户不需独立部署调度集群 | 需要多机 durable worker、长时任务 HA 和集中队列 |
| 直接依赖某 Agent SDK 编排全部流程 | 对单一 CLI 绑定较深，业务状态和产品工作流不应依赖 native session | 明确选定单一供应商且收益大于迁移成本 |

## 代价与风险

需要同时维护 Rust 与 TypeScript 以及 DTO 契约。Windows npm 包装脚本、CLI 升级、Tauri WebView、远端取消和断线恢复都需要专门探针。SQLite 支持本地场景，不承担跨机器共享数据库或多人写入的全部职责。

受管子进程与 worktree 不构成安全沙箱。若强隔离是上线前置条件，需单独验证隔离 Runner / 容器方案，不能因为应用采用 Rust 就宣称限制已落实。

## 验证与迁移路径

先验证一个真实 CLI 的结构产物与取消，再跑通需求→用例→本地执行→证据判定。随后用第二 Driver 检验端口是否合理，逐项接 SSH / WSL。失败时允许改选 Electron，但保持领域对象与协议稳定。

后续将 execution 服务抽为独立 Runner，用相同 manifest / task ID 与中心服务协作；数据库按 Repository 边界迁至服务持有的关系存储。该路径只预留边界，不在首期先建微服务。
