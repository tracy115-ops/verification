# 0.9.0 CLI 连通检查验收

设置的每个原生 Agent 可主动发送固定短请求。使用保存的实例路径、Claude 配置目录和模型，CodeAgent 保留空模型以复用其原生配置。界面明确说明可能产生费用，不在安装扫描或页面载入时自动发送请求。

## 判定和失效

仅当 CLI 协议正常终止且公开回复匹配固定标记时记录“短对话已验证”。认证失败、超时、取消、任意终止文本都不能记为成功。检查最多等待 60 秒的调用预算，支持原生取消；不保存或展示 CLI 原始响应正文。使用独立检查会话，不带用户 Spec 或历史聊天。

结果和时间戳在本次应用运行内共享至设置与编排节点，不跨重启持久化。配置保存时清除不同配置的结果；请求 ID 防止旧调用的迟到成功覆盖失效状态。原生终端登录或环境发生变化无法自动感知，应重新测试。短对话成功不认证结构化输出、工作流全链路、全部模型或第三方服务身份。

## 本轮验证

- 本机 Rust `turn` 原生入口使用 `claude.cmd`、现有配置目录、模型请求 `glm-5.3-flash`，固定短请求返回预期标记，状态 completed，退出码 0。实际走本机继承环境中的自定义网关；不能据此证明真实 GLM 服务或内部设备可用。
- 单测覆盖保存的实例/模型传输、认证错误、任意回复拒绝、取消与终态成功竞争、配置失效后的迟到回复。
- 生产界面离线 IPC 测试走设置输入模型、发送短测试、看到成功、修改模型、成功失效、再次返回认证失败。安装扫描、多实例绑定与 Provider 禁用等回归另行运行；模拟响应不计为实际模型验证。
- `npm run check` 的 210 项单测通过；Rust 工作区测试通过，3 项显式环境检查保持忽略。发布前另运行全量生产界面测试。
- 全量 59 项生产界面测试首次 58 项通过，引用修复路径暴露了分析重试控件的兄弟 key 冲突；修复后引用修复和连通检查两项复跑通过。GitHub 发布门禁再次运行全量检查，不能将首次全量记录写成零失败。

内部 CodeAgent 本机未安装；Pi 及其他环境认证不在这次新增检查的实际推理验收范围。文件选择器 GUI、目标机安装升级和两台物理设备协作沿用独立验收记录，本项不替代这些门槛。
