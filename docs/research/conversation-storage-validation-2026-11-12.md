## 核心检查

- 前端串行提交测试覆盖在途修改、合并待提交快照、失败保留内存、重试使用同一版本、无效回执及返回先前内容。
- 迁移测试覆盖保护副本失败、来源变化、离页、已有库连接、目标版本变化；失败不得切换来源或覆盖已有库。
- Rust 测试验证事务失败回滚、损坏/未知版本拒绝写入、行丢失校验、两个并发实例只有一个成功提交，以及强制杀死持有未提交事务的真实子进程后的恢复。
- 额外检查发现既有评审摘要依赖 JSON 字段顺序。会话行使用 RawValue 保留原始字段顺序和数值字面量；往返测试防止重新序列化使旧摘要失效。
- 界面专项覆盖迁移、重新加载、改名、从当前来源导出、清空与恢复；冲突时导出未提交内容、禁止新的 CLI 调用、读取失败不自动回退，以及保护备份失败不初始化数据库。
- 关闭保护测试验证数据库确认前不销毁窗口；提交失败时显示恢复入口，继续保留未保存表单/活动任务的原有确认流程。

## 原生实测

`tests/live/desktop-conversation-storage.spec.ts` 分迁移和重启两阶段执行。Release 构建通过临时 `TAURI_CONFIG` 使用 `dev.verification.workbench.audit01520261112` 标识，测试先通过原始 IPC 校验标识，再允许创建保护副本和数据库；正常应用命名空间不参与测试。

第一阶段通过界面迁移归档运行与会话输入，改名并等待 SQLite 已提交版本。随后终止由本次启动器创建、且已核对可执行路径的进程，再以同一隔离 WebView 配置启动新进程。第二阶段确认新名称、未发送输入、用例、产物字段顺序及审批记录均保留；旧浏览器副本仍为迁移前名称。未替换 IPC，没有新模型调用。测试后重新构建正常应用标识，审计标识不作为发行包交付。

截图与摘要见[验证产物](../examples/generated/conversation-storage-2026-11-12/README.md)。测试进程均已停止，正常应用数据未参与迁移测试。
