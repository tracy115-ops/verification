# 桌面协作与分步工作区验证

日期：2026-10-29。

## 已执行

- 104 项 Vitest 用例通过，覆盖服务地址校验、原生 API 转发、身份恢复、同令牌重试和按服务隔离凭据等契约。
- 21 项生产浏览器交互回归通过；4 项协作交互回归覆盖项目选择、生成候选、人工因子／场景编辑、评审同步、并发草稿、增量建议、用例和脚本覆盖。
- 5 项 Tauri Rust 测试通过，包括原生 HTTP 身份头与错误码保留、无 Origin 请求、跳转拒绝、响应大小和格式限制。Rust fmt、Clippy、Actionlint 与源文件约束通过。
- 本地重新构建真实 Tauri 桌面程序，启动两个进程，使用独立 WebView 用户目录；一份托管 Node 服务并作为管理员登录，另一份作为评审成员登录。未使用浏览器客户端代替桌面加入流程。

## 实际桌面链路

从设置启动服务，扫描得到地址后在软件内加入；管理员通过界面创建个人评审令牌、新建黑盒测试项目、生成明确标注为规则候选的场景并保存分工及契约依据。第二份桌面程序先提交无效令牌并得到拒绝，再以个人令牌登录、选择项目；场景为只读，评审可提交，第一份软件随后同步看到接受状态。

继续检查了服务切换、旧身份清理、localhost 地址规范化、刷新身份恢复，以及 Agent 接口指南使用真实主机地址。进入项目后连接步骤消失，内容步骤独立显示；成员、因子编辑和新增场景使用弹窗。浏览器测试还确认未保存修改会阻止切换工作步骤和项目，冲突不覆盖草稿。

## 边界

两个真实桌面进程位于同一台电脑；尚未验证另一台物理机器的防火墙、广播和路由。当前身份使用个人令牌，未实现账号密码注册或 SSO。本轮是协作操作验证，没有新增模型推理或业务脚本执行；候选生成和人工接受不证明题目已覆盖完整，也不代表测试通过。
