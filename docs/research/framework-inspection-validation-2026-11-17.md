## 真实桌面

以 `dev.verification.workbench.audit016framework` 独立应用标识编译 0.16.0 Release，再使用独立 WebView2 用户目录启动。测试先通过原始 IPC 核对应用标识，之后才编辑和保存框架；没有覆盖用户正常应用的数据。

`tests/live/desktop-framework-inspection.spec.ts` 通过实际窗口和原始 Tauri IPC：导入含顶层 `raise` 的框架仍获得解析结果，证明没有导入/执行框架；验证 `setUp` 仅作线索、语法错误行、缺失 SDK 的动态导出不被判定通过、缺少入口、保存/重载和会话检查过期。900/1500 像素及深浅主题检查无横向溢出，无未处理页面错误。

证据与摘要见[原生验收资产](../examples/generated/framework-inspection-2026-11-17/README.md)。验收后停止该确切路径的自有进程，重新编译正常应用标识，并确认可执行文件不再包含审计标识。

## 复验与边界

普通测试：`npm run check`、`npm run test:e2e`、`npm run test:e2e:production`、`npm run test:team:e2e`、`cargo test --workspace --locked`、`npm run verify:workflow`。

原生测试仅在显式隔离的应用标识下设置 `DESKTOP_INSPECTION_IDENTIFIER` 和 `DESKTOP_AUDIT_ENDPOINT` 后运行。检查本身不调用目标或模型；不能从这些结果推断认证、复位、并发或请求证据采集能力已可用。静态检查缓存仅存当前应用会话，未经检查的框架仍走原有预检与人工授权。
