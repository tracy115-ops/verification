# 0.8.2：普通对话认证及模型失败

日期：2026-11-05。用户截图显示未登录和模型不可用，随后确认原生终端也有相同问题。不能据此归因为应用丢失登录，更不能通过修改应用授予模型权限。

## 修复

- 原生分类器新增未登录提示匹配，Claude/CodeAgent 失败结果和 Codex 失败事件均返回 `cli_auth_failed`。仅在失败处理路径分类，正常回复不会因讨论登录问题变成失败。
- 普通消息使用独立失败提示，不声称已有流程产物或要求重试节点。认证及模型错误提供 Agent 设置入口。
- 消息保存实际 CLI、模型及调用 ID，刷新或切换当前 Agent 后不会误标旧回复；不复制完整提示词。旧消息可以继续读取，但没有元数据的旧回复不补造来源。
- CodeAgent 模型错误指向原生配置，不要求用户在应用输入模型 ID。版本探测仍不证明身份及推理可用。

## 验证

`npm run check` 通过：192 项前端单测、类型、生产构建、格式、版本及规模检查。`cargo test -p agent-runtime --locked` 37 项通过。生产前端 Playwright 43 项通过，包括四类普通对话失败、设置跳转、刷新及历史调用来源。

消息新增可选 CLI 元数据；新版本读取旧数据，含新字段的记录降级需使用升级前备份。
