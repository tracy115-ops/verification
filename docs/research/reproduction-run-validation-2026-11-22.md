# 应用内复跑验收 — 2026-11-22

## 输入与执行来源

设计和 Python 脚本来自历史已评审的房间容量任务，包含四个方法。本轮没有重新调用模型生成设计，也没有手工填写新的模型回复。历史材料用于建立源报告；随后全部基线及复跑均使用本机 Rust execution-runtime、真实 Python 子进程和本地 HTTP 测试目标。

目标服务可在相同地址切换缺陷/正确行为并延迟请求，仅用于受控对照。该基准证明复跑链路和证据关联，不代表未知题目的缺陷发现率或内部 CodeAgent 已验收。

## 真实桌面连续操作

使用隔离应用标识和 WebView 数据目录启动 Windows Release 桌面端 0.21.0，经 CDP 操作应用界面，未覆盖个人数据。

1. 打开实际基线报告，准备复跑；确认前无执行证据。
2. 勾选执行确认后真实运行四个方法，关联候选显示一次失败。
3. 再次准备、确认、执行，同一方法重复失败。
4. 延迟目标响应后开始第三轮，点击“停止执行”，运行标记取消。
5. 切换正确目标，点击“重新预检并确认执行”，验证执行 ID 更新、必须再次确认。
6. 执行四个方法全部通过，显示复跑结果不一致；刷新后从运行实例恢复相同结果。

源报告保持不变；三个复跑共使用四个不同执行 ID（包含取消与重试），产生零个新模型 turn。停止记录和旧执行计划已归档。截图和结构化摘要见[归档说明](../examples/generated/reproduction-run-2026-11-22/README.md)。
