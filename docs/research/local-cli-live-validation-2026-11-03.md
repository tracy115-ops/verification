## 真实发现与修复

1. **协议与正文共用 2 MiB 预算**：Claude 在没有公开正文时持续发出协议，51.7 秒时累计 2,097,205 字节、8,037 条记录后报 output_limit。将原始 stdout 协议预算拆为 16 MiB，公开累计正文保留 2 MiB，stderr 单独 128 KiB，单行继续为 256 KiB；超时和进程树回收保留。非公开内容仍不转成正文或存入日志。
2. **真实大协议复测**：相同需求请求在原任务重试成功；后续场景调用接收 4,917,476 字节、18,460 条记录，124 秒后取得公开正文和 result，最终正常退出。另用确定性子进程验证超过旧预算的私有协议可以完成，16 MiB 协议洪泛、2 MiB 公开正文和 128 KiB stderr 仍会被限制。
3. **范围说明被模型当作缺口**：早期真实 Claude 需求提取产生 8 条范围外问题，Codex 设计产生 4 条范围/执行状态说明。加强当前范围、固定输入、实际缺口与工作约束的提示；不在程序中自动过滤 Agent 缺口。之后仍有工作约束需求时，通过正式评审留下处理记录。独立复提取探针附带已确认范围决定，得到 8 条行为/输入/状态前置要求、0 个问题；不宣称单独一句提示词造成了全部改进。
4. **Pi 错误不具体**：实际模型歧义原来显示进程异常退出；增加稳定错误码和双语提示，指导使用 provider/model 并确认认证。未替用户登录或改写其 Provider 配置。

原始请求、公开回复、摘要和通过校验的产物见[生成档案](../examples/generated/local-cli-2026-11-03/README.md)。

## 验证限制

Computer Use 初始化、重试、重置后仍报告 native pipe unavailable；浏览器宿主也不可用，无法据此声称桌面点击链路完成。一次用于加载生产模块的 Vite SSR 辅助脚本自身超时，随后改用 Vitest 仅作 TypeScript 模块加载器；AgentPort 使用真实原生进程，没有 mock 或响应回放。

两条完整链路仅完成需求、因子、场景和用例设计；没有脚本或接口执行证据。内部 CodeAgent 的用户环境超时仍待验证；这次本地 output_limit 的直接原因已确认，但不能据此认定与用户此前的 CLI 超时同因。
