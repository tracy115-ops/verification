# 分批分析本地验证

日期：2026-10-31。范围为需求解析、场景设计、持久化及人工评审，不认证内部 CodeAgent 的模型推理。

## 本地结果

- `npm run check`：135 项 Vitest、版本同步、格式、源码规模检查、TypeScript 与生产构建通过。
- 生产构建 Playwright：6 项通过，包含从输入框提交大 Spec、第二批超时、刷新、界面点击重试、第一批只调用一次、剩余批次完成后停在人审。另验证旧引用修复、对话上下文、回复动效及面板布局。
- `npm run verify:workflow`：2 项通过，缺陷版与参考版均跑完整 13 节点，实际启动 Python，收集 36 项测试及 HTTP 证据。

分批专项测试覆盖全部原文字符和 Unicode、所有实际分析请求不超过 24,000 字节、持久化恢复、签名失效、结果摘要篡改、重复索引拒绝、取消后续跑、局部引用修复不跳过剩余批次、组间检查恢复，以及拒绝只关联单组的伪跨组场景。

大型设计状态机测试通过需求、场景、用例三个人工关口，合并 8 条需求及 32 个场景，再分批生成用例。测试 Agent 是确定性响应，只用于验证流程和校验约束，不代表这些场景来自真实 CodeAgent。

## 对旧执行夹具的修正

游戏执行夹具原来让每条需求和因子都引用整份题目，导致请求重复膨胀，且旧响应不能响应新的分组范围。已改为按接口段落和全局认证语句提取精确引用。原有 Python 脚本、36 项测试及缺陷版 / 参考版断言保持不变，完整执行回归重新通过。

## 验证边界

本机未安装内部 CodeAgent。输入预算、恢复及校验已验证；真实推理耗时和模型输出质量仍需安装环境复测。若小批次仍停在 system.init，没有模型回复，不能继续把原因归结为输入长度。截图 `.runtime/analysis-batches.png` 来自上述浏览器交互回归，CLI 边界为夹具。
