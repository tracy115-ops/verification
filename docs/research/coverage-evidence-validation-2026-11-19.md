# 覆盖与执行证据一致性验收

## 问题与修正

原覆盖判断和协作导出检查脚本文本与计划摘要，缺少完整用例映射、执行 ID、运行和会话归属及结果完整性检查。恢复数据包含这些不匹配时，可能把旧通过结果显示或导出给当前用例。

0.18.1 共用执行关联校验，复用现有执行计划和证据解码逻辑。当前脚本、方法用例映射以及问题列表须匹配预检快照，计划须属于当前运行和会话。证据须匹配计划及执行 ID，并逐一包含计划中的测试方法。

映射未核对时显示已声明覆盖，映射有效但证据不完整时显示尚未执行。协作导出保留脚本和映射，省去无法核对的执行结果。用例修订仍归档旧结果，并清除当前脚本、授权和证据。

## 验证方式

领域回归通过正常工作流入口完成夹具运行，再分别改变映射、运行 ID、会话 ID、执行 ID 和方法集合，验证个人覆盖与协作导出结果一致。用例修订回归检查通过结果失效和脚本映射包清除。

生产界面回归读取归档的原生执行资料，验证正常结果、不匹配执行 ID 和重关联用例三种情况下的覆盖提示及下载包。该回归使用历史执行资料。

复验入口为 `src/domain/runtime/execution-link.test.ts`、`tests/e2e/coverage-evidence-link.spec.ts` 和已有的用例修订、覆盖矩阵测试。

本地 `npm run check` 通过，包括 304 项单元测试、类型检查、版本和源码约束检查及生产构建。生产构建的 12 项相关界面回归通过，涵盖上述三种关联状态、脚本包下载、用例编辑、提议审核、覆盖矩阵及声明持久化。
