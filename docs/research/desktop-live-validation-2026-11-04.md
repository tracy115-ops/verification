# 真实桌面操作验收：订单支付重放

日期：2026-11-04。目标是验证用户实际入口到报告的完整链路，并查找只有实际操作才暴露的阻塞。

## 环境和方法

编译当前 Tauri/Rust 源码，运行真实桌面进程，使用独立 WebView 数据目录，通过 WebView2 的回环 CDP 调试端口连接 Playwright。操作真实页面按钮、表单、评审窗口和拖动分隔条；不替换原生 IPC、不向存储写入生成产物。只读读取存储用于断言和归档。

系统桌面控制服务持续报告 native pipe 不存在。最初 Vite 开发服务请求超时，因此改为生产构建及本地 `vite preview` 提供页面资源；原生 CLI、Python IPC 仍由当前真实桌面进程处理。本次不是安装器升级验收，也没有把开发服务空白页问题算作已经修复。

原生版本基线为 0.7.0；场景失败后重新构建前端并刷新，保留原任务，在同一实际桌面内验证本轮修复。请求模型为 `gpt-6.1-sol`，真实 Codex CLI。CodeAgent 本机未安装，不作兼容性结论。

## 实际操作

1. 设置中保存 Codex 模型、订单目标 `127.0.0.1` 地址与可信框架。框架来自仓库提供的 HTTP 测试框架，将默认夹具身份设为 `user-a`。
2. 在流程编排保存草稿，从会话选择已保存流程与完整本地执行范围，粘贴公开订单 Spec，点击调用。输入立即清空，展示实际任务字节数、回复动效、CLI 状态和公开回复。
3. 打开需求评审：11 条需求及原文引用通过校验，确认基线。场景首次返回发生映射错误；修复后刷新并在同一任务重试，生成 4 个因子、2 个场景，检查并确认覆盖。
4. 用例 Agent 生成 2 条用例，检查初始、创建、首次支付、顺序重放及只读观察断言，确认用例。
5. 脚本 Agent 生成 2 个方法，真实原生预检通过。打开执行确认，检查受控回环目标、脚本、框架及摘要；未勾选时执行按钮禁用，勾选后确认执行。
6. 真实 Python 调用目标，判定 Agent 分析实际证据，打开报告窗口。另将同一脚本通过原生执行器用于正确参考实现，未重写脚本或原任务结果。
7. 从会话右键进入对应资产，查看因子、来源及覆盖矩阵；刷新后完整流程、四次审批和面板宽度均保留。

另实际验证：设计运行时新建普通会话，Enter 发送另一条真实 CLI 请求并立即切回设计；回复正确归属不同会话。拖动右面板 360 → 460，收起展开后恢复，再用键盘调至 436，刷新仍保留。

## 结果与发现

完整流程 13/13，四次确认，无需新建任务恢复失败。需求/设计/用例及两个测试方法均由真实 Agent 调用产生。

| 目标 | 通过 | 断言失败 | 执行错误 | 跳过 | 请求 |
| --- | --- | --- | --- | --- | --- |
| 单一支付重放缺陷 | 1 | 1 | 0 | 0 | 26 |
| 正确参考实现 | 2 | 0 | 0 | 0 | 26 |

重复支付返回成功，但钱包从首次支付后的 `balance=80, charges=1` 变成 `60, 2`。实际余额断言失败；判定产生一个关联 C02、R08 的候选问题，并明确没有确认内部根因。C02 在余额断言停止，后续断言未完成；已记录响应仍显示库存为 2、订单 paid。覆盖矩阵将脚本关联和执行通过分开，不把失败方法显示为测试通过。

实测还发现场景 S01 引用了仅绑定 R07 的 F03，校验正确拒绝，但提示过于笼统，原重试任务缺少明确关联规则。本轮新增稳定错误码、受限的具体关联诊断、持久化及重试反馈，单次和分批均适用；不将无效设计变为有效产物，也不自动补造需求关系。实际重试通过新增规则恢复；精确反馈持久化由回归测试单独覆盖。

补充回归：`npm run check` 通过（168 项单测、类型、格式、约束及生产构建）；生产构建上的输入框、并发会话、右键资产入口和分析状态共 5 项 Playwright 测试通过。这些离线交互回归与上面的真实桌面/模型验收分别记录。归档的首次失败回复也加入回归测试，明确校验仍会拒绝该真实无效映射。
