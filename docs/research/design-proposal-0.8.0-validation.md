## 真实桌面操作

复用独立 WebView 的真实 Windows Tauri 进程及现有原生 CLI IPC，以生产前端经回环 CDP 操作页面，不注入模拟 IPC 或预制业务产物。原生运行基线为 0.7.0，功能在 0.7.2 基线工作树中接入，后续使用 0.8.0 前端构建验证；本次不是安装器或升级验收。

1. 打开此前真实生成的订单任务，点击“让 Agent 补充设计”，选择实际 Codex Profile（请求模型 gpt-6.1-sol）。输入：只新增聚焦重放前后钱包实际响应的独立场景，不改变现有场景或因子。
2. 原生 CLI 约 28 秒返回，仅新增 S03，关联已有 R07/R08/R09 和 F04 水平。请求约 14.7 KB，原有 2 个场景和 4 个因子、四次审批及原执行报告保持不变，提议处于待确认。
3. 打开差异窗口检查新增条目和来源，点击“合入并重新评审”。实际场景变为 3 条，原两条场景和所有因子逐字段相同；当前用例、脚本、预检、执行证据和报告被撤出，审批从 4 条保留为需求基线的 1 条，流程回到覆盖评审。
4. 刷新后状态保留。从会话打开只读修订历史，旧报告仍为 1 通过、1 失败、0 错误，候选问题“已支付订单顺序重放后钱包再次扣款”可以查看；旧报告内容与修订前完整一致。
5. 再通过实际 Codex 请求仅修改 S03 标题，差异窗口只显示名称一个字段。点击“暂不采纳”，刷新后原标题保留，历史仍只有一次实际合入修订。

未重新执行新设计的 Python；新设计仍需覆盖、用例及执行评审。此前执行证据不认证新增 S03。本轮实测证明个人任务的新增合入、修改提议拒绝、版本恢复和历史可读，不证明内部 CodeAgent 或局域网提议合入可用。

## 发现并修复的问题

- 提议录入过程中，用户消息时间在 React 延后更新中生成，可能排到 Agent 卡片后；改为提交时生成，统一同时间消息排序。
- 工作流关联的提议已有公开 CLI 卡片，额外等待组件会重复；现在避免重复展示。
- 新增差异的“原内容为空”列浪费空间，默认隐藏；因子水平及验证维度改为可读字段。
- 设计修订遗留旧 `resumedAt`，可能使新评审立即过期；新修订清除旧重试时间。取消固定 10 次设计修订计数，保留资源存储约束。
- 人工确认绑定具体提议内容摘要；异步合入期间若版本变化，则标记过期，不覆盖新版本。
