# 深层黑盒调查能力验证

日期：2026-11-03。第一阶段实现见[分期方案](../design/deep-blackbox-discovery.md)。

## 已接入产品链路

场景、分批场景、用例和脚本任务共用版本 1 的深度调查指引，检查状态序列、重放与作用域、守恒关系、可控依赖拒绝、并发历史和有来源的关系判定。约束为：只使用已批准范围与题目支持的可观测关系；没有依据的方法不自动成为覆盖缺口。脚本将一个旅程留在同一独立 test_ 方法内，使用运行时 ID 与前后观测，仍须映射到批准用例。

旧任务不会因升级获得“已完成深度探索”的新认证；后续实际调用的原始任务保留指引版本。类型化探索模型、自动序列生成、随机种子管理与复现缩减仍在计划阶段。

## 真实黑盒实验

订单题仅声明外部接口、库存/钱包/状态约束及可信框架。真实 Codex 一次生成 15 个测试方法；模型未收到目标源码或缺陷列表。先运行受控 Python，再用产品原生 execution-runtime 预检和执行同一脚本。

参考实现 15 项全通过。六个目标各只植入一个缺陷：取消重放库存、拒绝支付已提交、重复支付扣款、跨身份幂等共享、拒绝取消却改变状态、并发支付重复扣款；六个均被捕获，全部没有执行错误或跳过。普通正常路径在参考及所有变体上通过。追加多轮原脚本重放，仍六个命中、参考零误报。

记录保留输入 Schema、原文、公开回复、脚本摘要、每个可执行方法的需求映射、原生预检摘要和实际请求响应。脚本/映射/请求摘要在重放前验证，参考目标不通过或存在执行错误时，基准不能报告成功；没有人为把错误改成失败候选。

证据与复现命令见[生成档案](../examples/generated/deep-orders/README.md)。CI 与 Windows 打包增加 `--reuse-script` 复测，不触发模型推理。开发者必须显式提供 driver / model 才会重新生成。

## 可证明与尚不能证明的内容

可以证明该固定真实生成脚本能通过正式执行适配器发现上述多步骤违约，并且参考目标不误报。不能证明单独某条提示词产生了全部收益、发现所有深层问题、自动推断了根因，或内部 CodeAgent 已可用。此次没有进行桌面点击验收，也未把基准的执行计划当作用户项目的执行授权。
