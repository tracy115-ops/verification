日期：2026-10-28。此次以本地游戏平台题目检查界面与真实 CLI，不能把夹具回放当作用户实际操作的结果。

## 逐项检查

| 环节 | 本次验证 | 问题 / 状态 |
| --- | --- | --- |
| 会话入口 | 浏览器检查空状态、选择保存流程、范围与附件入口；浏览器禁用本机 CLI | 尚未通过桌面 GUI 从头完整操作；题目与项目任务尚无统一绑定 |

| 需求确认 | 检查真实运行与评审阻塞条件 | 原先无法逐条回答；现可保存澄清并重新确认，原始题目不变。需求本身仍不支持逐条编辑或退回 |
| 场景、因子、用例 | 夹具测试列表和追溯，团队浏览器测试因子 / 分工 / 评审 | 真实需求节点被阻塞，本轮未进行真实 CLI 的后续场景 / 用例分析；个人流程缺少独立因子模型与编辑 |
| 测试执行 / 结果 | 本地工作流回放夹具执行实际 Python / HTTP；浏览器测试执行设置 | 这不是本轮真实 CLI 从头生成的完整链路；框架只支持单文件 unittest |

真实调用结果在忽略目录 `.runtime/live-design/final.json`，记录包含真实模型输出和待确认状态；此前 `.runtime/workflow-validation/` 是设计产物回放加真实 Python 执行。两者不能混为一谈。实际待澄清问题包括未知错误优先级、状态查询和非法输入处理，不能靠测试者自行编造预期来通过评审。

追加验证：对上述真实需求的未规定项，测试人员仅将未知规则标为本次范围外，随后真实 Codex 生成 16 条场景、9 项缺口；这是带人工范围处理的验证。针对新版因子契约另发起真实调用，生成 11 个因子、36 个水平及 15 条场景；首次因校验器错误地禁止同一因子的多个水平而失败，修复后对原始响应重新校验通过，36 个水平均有场景引用，仍有 9 项规则缺口。这是结构与引用检查，不证明需求语义覆盖完整，也不是桌面 GUI 全链路验收。

## 本轮修改与仍需建设

移除过时的“只能设计评审”文案，完整流程按钮统一叫“调用流程”；待确认卡片前置，报告在流程步骤之前显示实际状态与数量；失败 / 中断 / 待确认在顶部明确显示；用例详情增加需求、前置条件、步骤和预期。

需求问题现可逐条保存回答，时间、问题和回答随运行记录保留，审批摘要绑定澄清，后续 Agent 收到澄清上下文。覆盖 / 用例评审缺口可以记录排除原因，排除项进入报告并使其无法完整判定；需求 / 因子 / 场景仍缺少逐条编辑及下游失效。之后才可声称真实任务从界面顺畅地完成自动分析。完整范围仍需桌面 UI、真实 CLI、真实框架和本地目标联合验收。
