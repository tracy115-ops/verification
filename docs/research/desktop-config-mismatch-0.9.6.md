# 桌面配置与验证配置不一致

2026-11-06，已安装应用为 0.9.5。读取最近失败日志和保存配置的元数据发现：Claude 仅绑定了启动文件，没有独立设置文件，约 1.4 秒即收到 `cli_auth_failed`；Codex 保存了含空格的模型显示名称，并返回 `cli_model_unavailable`。没有公开用户日志全文、路径或任何凭据。

此前工作流验证显式传入已验证的独立设置文件；两者配置不一致。因此真实驱动/引擎成功不能证明已安装桌面的当前配置可用。原设置把来源选择放在折叠项、模型与测试之后，也没有在测试前清楚展示差异，容易反复用错误来源测试。

## 修正

来源选择移到第一步；已保存绑定直接可见。Claude 可以只读查找常用 settings 文件，显式选择后保存，备份不自动启用。第三步展示测试使用的已保存来源。模型显示名风险另行提示。日志仅新增启动器/配置目录/设置文件是否绑定三个布尔字段，便于下一次定位，不记录路径、密钥或服务地址。

## 本轮证据

`tests/live/claude-settings.spec.ts` 在真实前端设置界面复现：默认来源认证失败 → 查找实际文件 → 点击选择 → 刷新恢复 → 点击短测试 → 已安装 Claude 经真实 Rust 驱动返回固定标记。移除子进程临时 Anthropic/OAuth 变量；第二轮保留与桌面相同的 `.cmd` 启动入口并验证绑定没有丢失。此项不预置模型成功回复。

文件扫描和模型调用由原生审计示例承接浏览器测试桥；这覆盖前端保存、序列化及真实原生函数，但不等同于 Tauri 窗口 IPC/系统文件对话框完整点按。原生自动化宿主仍提示 native pipe unavailable。现有安装的用户存储未被测试脚本修改；真实调用使用独立浏览器上下文。

## 手动选择才会调用的复验

先构建前端与 `cargo build -p agent-runtime --examples --locked`。设置 `CLI_AUDIT_SETTINGS_FILE`、`CLI_AUDIT_MODEL`，可选 `CLI_AUDIT_EXECUTABLE`，然后运行 `npx playwright test --config playwright.live.config.ts`。预期默认来源无认证、显式文件有效；若本机默认配置已可用，该复现前提不成立。测试可能产生模型费用，普通单测和 CI 不包含它，也不自动重试。

结果保存在忽略目录 `.runtime/live-settings-ui/`。普通离线回归另覆盖未自动选择备份、配置持久化、旧验证结果失效、窄窗口及元数据边界拒绝。
