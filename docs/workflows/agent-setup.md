# 配置原生 Agent

进入 **设置 → Agent 与 Provider → 配置并测试 Agent**，一次选择一个 Agent。按“选择 CLI 与配置来源 → 确认模型 → 测试已保存配置”操作。启动文件路径和认证配置来源是两回事，应用不会把选择启动器当成已完成登录配置。

## CodeAgent

选择 `codeagent / native`。模型使用其内部配置，不需要填写模型 ID、密钥或 Provider 地址。通常保持实例自动发现，直接点击“发送短测试”。未发现安装时，展开可选 CLI 实例，扫描或选择启动文件，例如实际安装的 `.bat` 文件；无需手动抄写完整路径。

## Claude、Codex 和 Pi

Codex、Claude 可以先点击“读取已有模型配置”，查看候选模型和来源，再点“采用此模型”。采用只填入模型草稿；点击“保存模型”，再点击“发送短测试”。读取不到时，在“确认模型”填写该 CLI 实际接受的模型 ID。Pi 当前仍需从 CLI 或服务提供方确认 ID；CodeAgent 使用内置模型。

候选不是服务端可用模型目录，也不保证认证或访问权限。读取限于 Codex 用户配置的顶层 `model`、Claude 用户或指定目录的 `settings.json` 中 `model` / `env.ANTHROPIC_MODEL` 及进程模型环境变量；不读取认证文件或解析包装脚本。项目、组织策略或启动脚本可能覆盖默认配置，最终以测试结果为准。不会自动覆盖或保存输入，也不会自动发起模型调用。

如果有多个安装实例，再展开 CLI 实例选择器。Claude 可额外浏览已有配置目录；默认保持继承。目录用于复用已有配置，不复制或修改凭据。

### 终端可用，但应用认证失败

若终端通过 `claude --settings <文件>` 加载独立配置，展开 **CLI 实例 → 选择设置文件…**，选择同一个可信文件，再点 **保存实例绑定**。支持 JSON 文件和 `.bak` 备份；不要仅因扩展名是备份就选用，先确认内容是你希望使用的配置。随后读取已有模型、保存模型、发送短测试。配置目录与独立设置文件含义不同：前者设置 `CLAUDE_CONFIG_DIR`，后者传入 `--settings`，两者可以同时使用。

0.9.6 起，第一步直接显示当前已保存的启动文件、配置目录、独立文件及模型。**查找已有设置文件**只读扫描常用目录，显示认证字段/密钥助手是否存在及备份标记；不显示凭据、不后台推理、不自动启用文件。确认后点击 **使用此设置文件**即保存绑定。其他目录用旁边的文件浏览按钮。第三步的“本次测试使用的已保存配置”可核对调用来源；更改配置会使旧测试结果失效。

模型值包含空格时会提示可能填写了显示名。例如界面显示名称不一定是服务端接受的 ID；优先读取已有模型配置再确认，不猜测或强制改写用户输入。

绑定文件用于短测试、会话和后续流程调用。旧运行保留原配置快照；修改绑定后旧连通结果失效。应用只保存文件路径，不复制凭据、不覆盖默认配置、不自动恢复备份。分享文档时移除本机绑定；不要共享含密钥的设置文件。

## 如何理解结果

- 安装探测只检查入口/版本，不证明认证有效。
- 短测试由用户主动发起，可能产生费用，支持取消；成功仅证明当前实例/模型能完成固定短对话。
- 认证失败应先修复对应 CLI 的登录或服务配置；修改模型/路径后旧测试结果失效。
- 测试结果在当前应用内保留，不跨重启；浏览器版不能直接调用本机 CLI。
