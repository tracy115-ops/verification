# 桌面会话 SQLite 使用与恢复

适用：0.15.0 起的桌面客户端。浏览器端继续使用原存储。

## 启用

1. 完成或取消活动任务，保存或放弃未保存表单。进入「设置 → 数据管理」。
2. 可先导出个人数据 JSON 到应用之外；应用内保护副本只有两份轮换，不是独立容灾备份。
3. 在「会话事务存储」点击「检查并迁移会话」，核对浏览器和数据库来源。
4. 没有数据库时，将保护当前数据并迁入；已有数据库时，只连接已有库，不合并或覆盖其内容。点击「保护数据并启用」后重新载入。
5. 查看「会话已写入 SQLite」与已提交版本。之后导出、清空和恢复会话均遵循这个来源，旧浏览器副本不再双写。

迁移的是会话、会话输入和运行内嵌产物。流程库、全局配置、CLI 日志及人工表单草稿仍有独立存储边界。0.14.x 不识别新的主库，不能用旧版读取迁移后的新修改；应用内升级拒绝降级，手工回退需明确使用匹配的保护副本。

## 保存失败或冲突

全局告警表示内容仍在内存中，没有收到数据库提交确认。磁盘、权限或占用问题可处理后重试。发生版本冲突时不会自动使用新版本号覆盖其他实例；先导出当前会话恢复副本，再重新打开应用读取数据库的新版本。新 Agent 调用会被阻止，已有任务仍可取消。

恢复副本可包含未提交内容，文件名为 `conversation-uncommitted-recovery.json`，不代表原数据库已成功保存。不要在导出完成前强杀应用。

## 无法启动读取

读取失败不会创建空会话库。可先重试读取；若选择「打开旧浏览器副本」，必须确认其可能过期。此操作仅切换来源，原 SQLite 文件保持保留。重新连接时仍通过数据管理检查已有数据库，保护当前浏览器来源后确认连接。

若需要从 JSON 恢复，可在浏览器副本模式下通过数据管理恢复后继续工作；这不等同于修复损坏的 SQLite 文件。原文件应保留供恢复检查，当前不提供一键覆盖损坏主库。缺失数据库、物理磁盘满、断电及跨存储恢复需按各自实际情况处理，不能将窗口草稿或两份影子副本当作完整容灾。
