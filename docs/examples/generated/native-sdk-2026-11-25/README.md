# 多文件 SDK 桌面验收

Windows 隔离桌面使用真实界面导入 `framework.py`、`sdk/__init__.py` 和 `sdk/client.py`，保存框架和本地目标，通过新会话提交 Spec。Claude 2.1.330 / glm-5.3-flash 生成需求、场景、用例、脚本和判定。审批由验收程序操作界面，执行使用原生 Python 和真实 HTTP；流程没有写入或替换 Agent 产物。

初次场景调用因逐段思考事件触发协议上限。将完整结果模式扩展到场景设计后，在同一隔离数据目录重建并启动桌面，从失败节点重试，沿用已确认需求和同一 SDK 快照。后续真实调用通过覆盖及用例评审。执行确认中展开 SDK 模块源码，明确确认后执行。

全部 13 节点成功，共四处审批。受控订单目标在支付返回 402 后错误地提交状态。生成脚本随后读回并捕获 1 项断言失败，零执行错误，报告列出 1 个待确认的候选缺陷，保留四条请求证据。验收核对了已执行的整包 SHA-256 和导入文件内容。

- `sdk-import.png` 和 `sdk-review.png` 对应目录导入和执行前审阅。
- `report.png`、`result.json` 和 `test_generated.py` 分别记录真实报告、执行结果和原始生成脚本。共享结果仅将 traceback 中的绝对路径缩短为文件名。
- 初始 0.24.1 标签用于发布 SDK。上述续跑使用包含主分支后续场景修复的本地构建，版本显示仍为 0.24.1。

测试目标和隔离桌面在验收结束后关闭。此例使用本地受控 SDK，第三方项目依赖和目标环境仍需独立验证。
