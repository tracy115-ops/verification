# 0.9.6 Release 原生桌面端到端验证

本目录为 2026-11-06 实际生成与执行的产物，未手工填写模型回复或执行结果。使用 GitHub v0.9.6 已发布 NSIS 包内未修改的 Release 可执行文件，先核对安装包 SHA-256，再解包启动；没有覆盖现有安装。`provenance.json` 记录发布提交、二进制摘要、步骤状态和文件摘要。

## 实际走过的路径

在真实 Tauri / WebView2 窗口，通过原有 IPC 完成：选择 Claude 设置来源及启动器 → 保存模型和短测 → 保存框架与目标 → 保存编排 → 新建会话提交 Spec → 需求评审 → 场景评审 → 用例评审 → 生成 Python → 原生预检 → 查看脚本并确认执行 → HTTP 实测 → Agent 判定 → 打开报告。共 13 个步骤、4 次审计脚本点击的评审批准；从短测完成至报告打开约 363 秒。

没有替换 `__TAURI_INTERNALS__`、预置会话/产物、设置离线模型返回值，或用单独的引擎循环替代界面。控制的是 Release 程序自身 WebView；外层窗口框架、系统文件选择对话框和本机安装升级未在此项内重复操作。安装器安装/升级冒烟与本版本 CI 已独立通过。

## 结果

- 5 条需求、4 个因子、4 个场景、4 条用例由真实已安装 Claude 生成，请求模型为 `glm-5.3-flash`。这是请求 ID，不独立证明上游服务实际模型身份。
- 真实 Python 测试为 **3 通过、1 断言失败、0 错误、0 跳过**，共 8 条请求记录（含逐例 reset）。容量 1 的创建请求返回 201，违反题目预期 400，形成一条候选缺陷，未自动提交外部缺陷系统。
- 同一生成脚本 SHA-256 保持不变：正确参考目标 **4 全通过**；缺陷目标重复执行仍为 **3 通过、1 失败**。这两条对照通过原生执行 helper 复跑，不冒充第二次 UI 设计流程。

`source.txt` 是唯一题目；`requirements.json`、`design.json`、`cases.json`、`implementation.json`、`test_rooms.py` 是实际生成产物；`evidence.redacted.json`、`report.json` 是桌面调用的执行结果与报告；`controls.json` 是执行对照；`final-report.png` 是真正 Release WebView 的最终画面。公开证据仅把 traceback 的本机用户目录前缀替换为占位符，断言和请求响应未修改；原始证据保留在本机忽略目录。原生结果/证据摘要仍指原始记录，公开脱敏文件的摘要单列于 provenance，不能混为同一个文件摘要。
