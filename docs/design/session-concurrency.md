# 会话并发与归属

## 执行模型

会话选择与后台执行解耦。React 按 session ID 保存控制器、运行状态、公开流式回复和调用错误；同一会话防止重复发送，不同会话可并行对话或调用工作流。最终消息按请求捕获的会话 ID 写入，流程更新沿用 run.sessionId，不依赖屏幕上当前选中的会话。

会话列表允许执行期间搜索、新建、切换和查看其他资产，并标记后台运行会话。取消只查找目标会话控制器。执行中的会话禁止删除和重命名，防止完成回写覆盖；其他会话管理不被全局锁住。

原生 CLI 注册表按 turn ID 保存会话及取消信号，最多 8 项；同一会话和同一 turn ID 不能重复占位。Python 注册表允许最多 8 个不同 execution ID。超过容量会明确失败，目前没有等待队列、限流退避或可配置并发数。

升级安装仍需要全局独占活动锁；界面的数据恢复和关闭提示使用 anyBusy，而会话输入与停止按钮使用当前会话 busy。应用卸载当前工作区 Hook 时取消全部本地控制器，切换会话本身不取消任务。

## 验证与边界

- Hook 回归：同时启动两个会话，分别接收输出；切换后只见各自流；取消甲后乙继续，结果写入正确会话。
- 生产构建 Playwright：通过真实控件选择 CodeAgent 夹具、发送两个会话、执行中切换，核对最终回复及后台标记；不调用模型。
- Rust 注册表测试：独立会话占位、同会话重复拒绝、取消隔离、容量边界，以及 Python 独立任务。

本轮不保证内部 CodeAgent 的服务端模型额度，也不隔离被测外部系统的状态。多个测试流程访问同一目标时，需要独立身份和测试数据。关闭整个应用会停止任务；本轮不提供脱离桌面进程的常驻调度服务。
