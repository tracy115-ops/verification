# 会话调用与设置方案

## 产品入口

应用内会话是主入口，底层调用本机安装的 Codex、Claude Code 或 Pi CLI。用户先讨论需求，再明确选择已保存流程并输入 Spec。流程编排负责编辑，设置负责全局配置，运行实例负责追溯历史，验证资产负责查看产物。

- **设置 / 通用**：界面语言、主题，独立保存到当前设备。
- **设置 / Agent 与 Provider**：CLI 安装 / 版本探测、可复用 Profile、模型与 Provider 元数据。探测不发起推理；安装仍由用户在本机完成。
- **流程 / 节点配置**：角色、Profile 绑定、超时、输入输出。全局配置入口可从节点直达。
- **会话**：消息、流式输出、保存流程选择器、Spec 附件、停止按钮；右侧显示节点进度、确认卡片和产物。

执行目标、模板仓库、凭据、通知和策略等后续全局能力也归设置，但只在对应服务实现后开放。

## 从保存到调用

1. 在编排中保存流程；当前只维护一份可导入导出的活动定义。
2. 会话选择流程，或输入 `/run general-testing 账户连续失败5次后锁定。`。
3. 创建运行时复制保存版本、输入、节点计划和当前 Profile；后续编辑不会改变旧记录。
4. 当前计划为导入 → 需求提取 → 需求确认 → 场景设计 → 覆盖确认 → 用例生成 → 用例确认。模板中的脚本开发、预检、执行与判定节点不在本次范围，界面始终显示“尚未执行测试”。
5. 系统调度各节点并验证结构；CLI 正常退出不能代替产物合格和人工确认。非当前支持的图结构在调用前拒绝。

普通对话每次启动短生命周期 CLI，通过最近 20 条已完成消息重建上下文；当前不恢复 CLI 原生会话。流程调用需要用户明确操作，尚未实现模型自行选择工具调用流程，也不支持 Agent 自动生成编排草稿。

## 确认与追溯

需求必须带可在 Spec 中唯一定位的原文引用；场景关联有效需求 ID；用例关联有效场景，并与场景需求集合一致。需求疑问、显式覆盖缺口、无场景的需求或无用例的场景会阻止确认。这些检查证明结构与关联一致，不能证明 Agent 已找全需求。

确认摘要绑定保存定义、Spec、节点与输入产物；输入变化会拒绝旧确认。当前不提供产物直接编辑，用户需补充 Spec 后重新调用。实际产物可在会话和验证资产查看，原有演示数据继续显示示例标记。

## CLI 驱动与恢复

前端通过 `AgentPort` 接口，Tauri IPC 负责启动已知 CLI，Rust 归一文本、会话 ID、活动与心跳事件。提示通过 stdin 传入，模型参数独立传参；不拼接用户 shell 命令。隐藏推理内容不进入消息视图。

原生配置复用 CLI 已有登录；自定义 Provider 当前仅保存元数据，真实调用明确拒绝。设计调用限制工具能力，Codex 使用 read-only 与关闭 shell，Claude / Pi 关闭工具及 MCP。已有 CLI 配置仍可能影响行为，这不构成企业执行沙箱或能力认证。

单次请求最长 600 秒、提示最多 128 KiB、输出最多 2 MiB、单事件行最多 256 KiB；节点另受流程截止时间和尝试次数约束。当前桌面全局串行调用，超时、取消或消费端断开会停止受管进程；Windows Job Object 清理子进程树。

会话重载将活动运行标为中断，保留未结束 turn ID。重试前先请求停止旧调用；普通消息需要显式“停止上次调用”后继续。不存在自动付费重试。当前使用本地存储，不提供数据库事务、完整审计或跨设备恢复。

协议依据：[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)、[Claude Code headless](https://code.claude.com/docs/en/headless)、[Pi JSON 模式](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/json.md)。实际支持仍以本机验证结果为准。
