# 结构化场景旅程

## 目的和使用

对题目明确支持的多次调用，场景可以附带 `journey` v1，记录初始状态、前置条件和有序步骤。每步包含执行前后状态、操作、可观测结果、关联需求及原文依据。拒绝但状态不变可以表示为自环。

Agent 的设计、分批设计及增量提议共用该结构；单次请求或缺少状态规则时可以不填写。保留旧场景兼容性，不要求每个输入边界都复制一份旅程。当前是可评审路径，不是自动状态空间搜索。

在当前会话的“验证资产 → 场景设计与映射 → 编辑”中可启用或修改旅程。按步骤标签切换编辑，追加或删除步骤。每步选择本场景关联的需求后带入原文，可缩选为准确引用。查看场景及评审用例时显示同一旅程，便于核对操作顺序和逐步观察。

0.22.1 起，带旅程的场景详情优先显示结构化路径；长策略、场景说明和因子组合可展开核对，避免说明文字把关键步骤推到页面底部。普通无旅程场景保留原展示方式。

## 数据与校验

- 版本为 1，路径 2–12 步，步骤 ID 在场景内唯一。
- 首步起始状态等于初始状态，后续步骤承接上一结果；步骤可以保持原状态。
- 每步需求必须属于本场景，原文引用必须来自该需求；外部输出同时进行结构与关系校验。
- 合并分析批次时保留旅程，不将具有不同路径的场景当成重复内容。步骤 ID 以场景为作用域。
- 人工修改使用既有设计修订机制：保留旧快照，重新打开覆盖评审，使下游用例、脚本、执行授权与覆盖证据失效。

## 下游和边界

用例、脚本任务收到已批准旅程及共同调查指引，要求保持前置条件、顺序和观察结果。结构检查证明引用和路径连续，不证明操作可达、断言语义正确或测试已执行。当前未建立逐步骤到 Python 断言的静态证明，仍需用例评审和真实执行证据。

个人协作补充包保留完整设计及旅程；当前共享项目转换仍使用既有场景/用例模型，尚无团队旅程编辑及逐步骤覆盖协议。最小化器、组合搜索、自动批量探索和跨场景状态模型留待后续实现。
