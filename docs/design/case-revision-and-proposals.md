# 用例补充与增量提议

## 操作入口

每个会话的验证资产绑定当前运行。确认需求和场景后，测试用例页支持新增、编辑和复制；编辑器依次展示关联与范围、步骤与断言、变更说明。新增用例必须关联已存在的场景和需求，明确前置条件、动作、可观察结果及具体断言。复制仅创建编辑起点，不代表增加有效覆盖。

覆盖矩阵和用例评审可将缺口送回原会话。会话切换到“修改用例”后，Agent 只提交增量新增或更新，不直接覆盖用例集。右侧展示待审核提议，逐条查看差异再合入或拒绝。有未解答问题、引用错误或基线过期时禁止合入。

## 变更边界

人工和审核通过的 Agent 提议共用修订服务。保存修改原因和来源，归档旧产物、审批及步骤，保留已确认的需求和场景；重新打开用例评审。按节点依赖遍历清除脚本、覆盖声明、执行授权、证据及报告的当前有效状态，即使编排节点顺序改变也不能复用旧绿灯。旧结果留作历史，不计作修订后执行结果。

Agent 提议绑定运行及基线摘要。设计变更使待合入用例提议过期；用例变更使其他待合入用例提议过期。传输及导入时校验结构、所有权、ID 和映射关系。运行中禁止直接改写用例。

## 草稿与限制

关闭弹窗或切换会话保留窗口内未保存草稿，并纳入全局未保存修改检查。基线发生变化时阻止覆盖，用户可显式放弃草稿；删除所属会话也删除草稿。保存成功后选中新用例并取消旧筛选。

本期不提供隐式删除、自动合入或自动执行。个人草稿仍非崩溃恢复存储；多人共享项目继续使用已有版本检查和提议接口，个人修订不会自动广播。结构正确不证明断言充分，需要原文复核和真实框架验证。
