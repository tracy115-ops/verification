# 框架接入检查

0.16.0 首批范围：提前发现单文件 Python 框架的明显接入问题，减少生成脚本后才暴露的不兼容。入口为设置 → 测试框架与执行 → 导入/编辑源码 → 检查当前框架。

## 检查和展示

桌面使用当前填写的 Python 命令，启动固定的 AST 检查程序。单文件输入最多 60000 个 UTF-8 字节。框架仅作为文本读取，绝不导入框架模块，不调用复位、测试、模型或目标接口。检查程序有 10 秒进程时限，支持取消、断开消费者停止和临时目录清理。

报告区分三类结果：

- 明确问题：Python 低于 3.11、语法错误、文件超过 2000 行、函数超过 200 行、未发现 `BlackBoxCase` 入口。
- 静态声明：语法可解析、规模符合限制、入口直接继承 `unittest.TestCase`。这不证明依赖、运行行为或目标环境可用。
- 未确认：入口由 SDK 导入、赋值或间接继承提供，需要后续执行确认。`setUp`、`tearDown` 和环境变量引用仅作为源码线索。

成功和未确认报告默认折叠；明确问题默认展开。行号可定位回源码。浏览器可以编辑和保存框架，但不提供本地 Python 检查。

## 状态与流程连续性

结果按完整源码和 Python 命令绑定，仅缓存当前应用会话最近 20 份。修改后不套用其他版本的结果；失败重查清除旧成功，取消和迟到响应不能恢复旧结果。重新加载或恢复个人备份后需重新检查；同名解释器在磁盘上被替换时也应主动重查。

已知存在明确问题的同一份框架会在完整流程发送前阻止调用，并保留输入；仅设计评审仍可继续。未检查及动态入口保持兼容，状态明确显示为未检查/未确认，不伪造通过。实际执行仍走原有脚本预检和人工授权。

检查过的框架用于创建完整运行时，报告作为 `framework.inspection` 产物固化，包含源码 SHA-256、Python 命令、版本和检查时间。运行快照已有框架原文；报告不重复存放源码。检查记录不修改历史执行证据。

## 模块和边界

`execution-runtime` 提供检查程序及受管理进程；Tauri IPC 负责并发预约、升级活动锁和诊断；前端服务校验报告、源码摘要和请求代次；领域层决定发送准备状态。日志只含检查 ID、稳定状态和错误码。

此版不支持多文件 SDK、依赖安装、pytest、远程执行，也不证明 reset、并发或请求证据采集的有效性。后续分为受控多文件导入、环境/依赖声明、最小授权连通用例、复位/证据运行契约验证，逐项验收后再展示能力通过。

## 多文件 SDK 的首个可验收范围

先支持本地 unittest 的纯 Python 包，沿用 `framework.py` 导出 `BlackBoxCase` 的入口契约。导入后冻结相对路径与文件内容，限制文件数和总大小，拒绝路径越界、符号链接和与固定运行文件冲突的名称。预检逐文件解析源码，报告文件名和行号。依赖声明用于检查解释器环境的缺项，安装依赖需要独立操作。

计划摘要覆盖入口文件和所有模块。预检、执行及复跑都使用同一份包快照，模块内容变化使旧授权失效。导出复现资料时携带该快照，以便在同样的解释器环境重新预检。

首个验收用例使用入口、客户端和证据记录模块分离的 SDK，从桌面导入到报告走通。分别确认缺依赖和改动任一模块的恢复路径，以及复位和请求证据来自实际运行。单文件任务和旧报告继续使用原有摘要口径。
