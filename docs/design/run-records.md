# 运行实例的用途与交互

运行实例是跨会话的流程排查和追溯入口。同一会话可以多次调用流程；每次运行有独立 ID、编排快照、审批、产物与执行证据。会话列表负责继续对话，运行列表负责找到需要处理的调用和核对历史结果。

页面使用紧凑的搜索／状态筛选、运行列表和详情布局。支持搜索会话名、流程名、运行 ID 和错误码；「需要处理」包括失败、中断及等待评审。按实际保存的创建时间排序，不依赖会话数组顺序。

详情展示步骤进度、待处理节点、失败原因，以及需求、因子、场景和用例数量。逐节点打开既有产物工作区；「验证资产」绑定本次运行，不能切换成同一会话的最新运行。「去会话处理」回到同一调用的评审和恢复入口，不在历史页自动重试 Agent 或执行测试。

工作流完成和测试通过分别呈现。设计流程明确显示未执行测试；存在执行证据但没有最终报告时，说明报告尚未生成；有报告时读取已保存的通过／失败／候选缺陷计数。历史 CLI 用时只合计已记录且已结束的调用时间，排除人工等待和测试执行；没有原始记录时显示未记录，不估计总耗时。

当前页面读取本机运行记录，不是团队调度中心。共享项目与个人运行仍按各自的存储与交接规则处理。

## 2026-10-29 验证

100 项单元测试与 21 项生产界面测试通过。新增交互验证失败任务筛选、900px 宽度、节点产物打开，以及同会话历史运行资产绑定。实际 Tauri 中核对既有完整流程：10 条需求、10 个因子、17 个场景、36 条用例；报告读取到 33 通过、11 断言失败、8 组候选缺陷。另一个真实设计任务的 4 条用例明确显示未执行，打开资产仍绑定该任务。本轮只读取既有证据，未新增推理或执行测试。
