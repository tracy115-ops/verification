# 候选问题人工复核

## 入口与状态

会话的流程面板和运行实例详情均可打开报告。在候选问题详情中展开“记录复核结论”，选择待补证据、确认缺陷或误报，并填写理由。候选列表显示当前复核状态，历史记录可展开和单独导出。

复核只对已完成运行开放。理由最多 4,000 字，每个运行最多保存 200 条事件。结论绑定运行、会话、报告摘要、候选 ID 和执行证据摘要。状态更新追加事件，原始 Agent 判断、测试计数和执行证据保持为可核对的记录。

## 证据与变更

确认缺陷或误报前，核对当前脚本映射、预检计划、执行 ID、结果集合、失败方法及用例原文关联。资料缺失时可记录待补证据，界面会说明受阻原因。新报告使用新的摘要，旧报告的复核结论保留在历史中。

人工结论用于记录复核者的判断。稳定性复跑、修复复测和团队缺陷状态流转仍在后续计划中。

## 保存与草稿

复核记录作为版本化 `CandidateReviewLog` 产物随个人运行保存，使用当前会话仓库及既有备份机制。应用层在异步保存前后检查运行对象是否仍为当前版本，阻止过期操作覆盖新记录。导入时检查日志结构、状态、时间及运行归属。

未提交理由接入窗口内草稿保护，关闭报告后重新打开可以继续填写，也能在数据管理中查看或放弃。关闭应用前应保存或明确放弃草稿。复核导出包含该候选的状态变更、理由、时间和证据关联标识。
