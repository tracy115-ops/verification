# 对话驱动的设计增量提议

状态：0.8.0 实现个人验证任务的因子、场景新增与修改。共享项目分工、需求规则编辑及任意工具调用不在本轮范围。

## 入口与交互

会话选择“修改当前设计”，或点击右侧“让 Agent 补充设计”，输入需要的变化。普通对话继续用于讨论，修改模式使用已确认需求和当前设计，避免把整个会话历史重复提交。

Agent 返回有界的新增/修改列表和未解决问题。原设计保持不变，中间记录实际任务与公开回复，右侧出现提议卡。差异窗口按条目查看：新增只显示建议内容，修改展示前后字段；原始 JSON 收纳在详情中。用户可合入或暂不采纳，决定及提议都保留。继续修改待确认提议时，任务会携带最近的待确认提议，并要求基于当前正式设计生成替代候选；不会假定旧提议已经生效。

## 契约与校验

- `design.propose` 使用现有 AgentPort、原生 CLI Profile、超时、取消和公开记录服务。CodeAgent 仍遵守内置模型选择逻辑；本轮实际推理只验证 Codex。
- 版本 1 的 `DesignChangeProposal` 绑定任务、CLI 调用、需求/设计摘要、澄清及排除记录。每类最多 20 个变更条目；仅允许 add/update，不支持删除或改写需求。已有 ID 不能以新增覆盖，新 ID 不能以修改伪造。
- 合成后的完整设计仍校验来源、需求、因子水平及交叉映射；没有业务依据的预期应成为问题，不能自动补造规则。有问题、无有效变化、源版本过期时不得合入。
- 确认绑定界面所示提议摘要，合入前重新核对内容摘要。异步计算期间运行发生变化时，不覆盖新版本；并发、取消、刷新和无效导入均有回归覆盖。
- 最多同时保留 20 条待确认提议；处理已有提议后可以继续生成，已决记录保留。设计修订不再有固定 10 次计数限制，仍受个人数据存储限额约束。

## 合入与恢复

合入复用 `reviseDesign`：保留需求基线及其批准，归档原设计、步骤、用例、脚本、执行证据、报告和审批。覆盖评审及其后继节点重新进入待处理状态，原覆盖声明和执行授权不能沿用。历史修订记录 Agent 提议 ID、调用 ID 和人工确认后的来源。

历史设计和结果可在会话的修订记录中只读打开；不能由历史页编辑当前状态。新修订重置本轮评审计时，清除旧重试时间，避免立即继承过期截止时间。运行中可起草修改，实际生成仍遵守当前会话的任务并发控制；这不是自动在途改写或无限等待。

## 仍需后续实现

需求/用例等常规评审的完整条目工作区、共享项目提议合入、负责人操作和逐断言覆盖追踪仍在后续计划。个人设计提议合入不自动发布到共享项目，也不会自动执行脚本或提交缺陷。
