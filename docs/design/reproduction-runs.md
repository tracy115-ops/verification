# 应用内候选问题复跑

## 操作与边界

在桌面报告的候选问题中点击“预检并准备复跑”。工作台新建独立运行，沿用原任务已评审的需求、设计、用例、完整脚本和框架，从环境预检开始，在执行计划评审处暂停。核对目标并勾选确认后才执行；此路径不调用模型。

复跑执行完整已批准脚本，选中的候选用于定位和比较关联测试方法，不会静默裁剪脚本。原报告和人工复核历史保持原样。复跑产物标明“沿用原产物”，不能直接修改继承的设计；需要修改时返回原设计任务修订、重新审批。

## 运行与证据模型

`ReproductionSource` v1 记录原运行、候选、报告/执行计划/证据摘要、源码 SHA-256、目标及继承节点。运行有新的 UUID；预检生成独立执行 ID、工作目录及计划，人工确认绑定本次计划。执行结束保存实际 `EvidenceBundle`，不生成新的模型判定报告。

复跑计划选取原执行节点及其依赖；原预检及其下游重新执行，自定义人工关口保留。不能支持的下游操作阻止创建。加载和保存同时校验来源结构、继承节点及允许的操作。

## 结果展示

会话显示复跑活动和证据入口；右侧及运行实例显示本次完整脚本结果、关联方法的累计观察。统计仅纳入同一原候选、原报告/计划/证据、脚本、框架、目标配置及 Python 版本，且执行证据与本次计划匹配的运行。

一次失败显示“观察到一次失败”，多次均失败显示“多次复跑均失败”；通过和失败并存显示“复跑结果不一致”。错误或跳过显示待核对。结果不一致可能来自目标修复、数据状态或不稳定行为，不能自动断言根因或修改候选人工结论。目标后端版本无法自动识别。

## 停止、恢复与容量

停止实际执行会终止受管进程。重试执行先归档原计划及停止/失败结果，再重做预检并要求人工确认，避免复用单次执行工作目录和旧授权。刷新后未完成运行标记中断，不自动执行。每次重试不设次数上限，仍受现有个人存储容量约束。

本版提供逐次准备和确认；无人值守批量复跑、证据压缩、最小化复现和自动根因确认尚未实现。[验收记录](../research/reproduction-run-validation-2026-11-22.md)区分真实执行和离线 UI 契约。
