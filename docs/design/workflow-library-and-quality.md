# 流程库与测试设计质量

2026-11-09。目标：用户从 Spec 开始，选择适合任务的可复用流程，得到可评审、可追溯且有明确缺口的设计。

## 流程模板、会话和运行的边界

- **流程库**管理多份模板：新建、复制、搜索、切换、删除。名称在「流程设置」修改；每份模板独立递增本地修订号。新建从可执行的通用测试流程开始，而不是创建无法运行的空画布。
- **会话**保存所选模板 ID、Agent、执行范围和 Spec 草稿。编辑器切换模板不能改变已选择的会话。界面显示本次将使用的已保存修订；未保存修改不参加调用。
- **运行**保存调用时的完整快照，后续修改或删除模板不改变历史运行、重试及产物。删除后，仍引用该模板的会话必须重新选择，不能静默回退。
- `/run ID Spec` 与界面调用采用相同的流程解析及调用前检查。新增到设计路径末端的人工复核必须进入实际运行，不能只显示在画布上。

## 保存与恢复

原 `verification-workbench.document.v1` 键升级为 `libraryVersion: 1 / activeId / documents` 容器。旧单文档只读加载，第一次成功写入时迁移；一次 `setItem` 保存整个流程库，失败不更新内存中的已保存状态。重复 ID、无效活动 ID、超过 100 个模板或 200 万字符的写入拒绝。

个人备份、恢复及 SQLite 影子副本继续使用原键，备份校验同时兼容旧单文档和新容器。此变更不提供旧版本应用读取新容器的降级支持；升级前应保留原备份。个人业务主存储仍需后续事务化迁移。

## 质量检查与深度设计

覆盖矩阵新增可复核的结构检查：逐个因子水平是否存在显式场景映射、逐个场景是否存在用例，以及需求问题和设计缺口。条目可直接跳转到对应因子或场景，继续人工补充或通过会话提交 Agent 增量提议。未生成用例时显示待承接，不伪装为执行失败。

结构检查不能证明业务覆盖全面，尤其不能把单因子覆盖当成组合覆盖。当前生成指引已经包含状态旅程、关系判定、异常、并发和恢复；后续必须补类型化约束与可观测判定依据，以及独立题目的质量评测，不能以更多条目或提示词代替验证。

## 整体后续顺序

| 顺序 | 产品链路 | 验收重点 |
| --- | --- | --- |
| P0 | 数据与长任务连续性 | 个人事务存储；强杀恢复；模板、Spec 变更使下游确认失效 |
| P1 | Spec → 需求 → 因子 → 场景 | 原文锚点；验收规则粒度；约束不可达组合；边界、状态、权限、并发、补偿恢复的逐项适用性评审 |
| P1 | 场景 → 有价值用例 | 明确前置状态、动作序列和可观测断言；用例去重；保留未知预期；人工及 Agent 增量补充后重审 |
| P1 | 用例 → 脚本 → 证据 | 框架能力先检查；脚本映射与手工声明分开；断言到达证据；误报复核与修复复测 |
| P1 | 多人共享评审 | 两台真实客户端分别补充、评审、冲突和重连；个人运行与共享版本显式发布/合入 |
| 发布门槛 | 独立黑盒题目 | 未参与调试的 Spec 与框架，由真实 Agent 新生成脚本；同时跑缺陷目标和正确参考目标，报告独立缺陷命中、误报、复现率及耗时 |

每轮回归包含会话、编排、资产、运行、设置、协作的导航连续性及中英文/明暗主题/窗口宽度；协议替身、历史回放、真实模型调用分别记录。
