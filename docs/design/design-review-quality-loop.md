# 设计缺口的评审与补充闭环

2026-11-09，0.13.0 增量。目标是让发现的漏测项进入可追溯的补充和重新评审，而不是只显示一组覆盖数字。

## 状态与计数

缺口由当前任务的需求、设计、用例及评审记录派生，不新增另一份可被手工改绿的状态源。

| 状态 | 含义 | 覆盖计数 |
| --- | --- | --- |
| 待处理 | 已有设计或用例中仍缺少明确关联，或问题未澄清 | 保持实际值 |
| 待生成 | 设计已有场景，但用例尚未生成 | 不作为已生成用例的遗漏；执行显示待生成 |
| 已澄清 | 对原问题有已保存的回答 | 保留回答，不增加场景/用例数量 |
| 已记录排除原因 | 对本评审阶段的具体问题有排除理由 | 保留理由，不作为已覆盖 |

排除按节点及原问题匹配，其他阶段的相同字符串不能替代当前阶段的评审。用例统计使用当前执行范围；排除的草稿用例不能继续提高场景或需求覆盖。无可统计用例时不显示“通过 0/0”。

## 补充入口

覆盖评审或覆盖矩阵中，未处理的设计缺口可带回原会话。入口明确绑定任务和运行，不自动发起 CLI 调用。已有输入、Agent 选择和原始内容保留；重复带入相同末尾请求不会重复追加。超出输入容量或任务已变化时拒绝带入并保留草稿。

每次带入最多 10 项、每项最多 240 字符的预览，完整来源和设计仍由任务上下文提供。此入口只提出因子/场景增量修改；已明确排除的项与等待用例生成的场景不作为自动补充目标。对未知规则应提出问题，不编造预期。

用户发送后，沿用现有“Agent 修改提议 → 查看差异 → 人工合入 → 重新评审”的机制。尚未支持通过此入口直接修改用例或解算所有约束组合。

## 变更后的失效传播

设计合入后沿依赖边遍历全部后继节点，不能依赖 JSON 节点数组或画布顺序。用例、脚本、执行计划、证据及相关确认失效；历史快照保留。其他未合入提议标记过期，避免基于旧设计继续合入或占据待处理数量。

测试必须包含反序存储的有效图，并证明旧用例和旧确认不会保留在当前结果中。纯函数与提议契约测试验证规则；页面测试验证缺口带入和审核；原生桌面测试验证实际窗口中的带入与人工修复。受控历史结构及协议替身不作为新题目模型发现能力的证据。

## 后续质量门槛

下一阶段仍需补齐用例条目的人工/Agent 增量编辑、类型化约束及状态旅程评审，以及独立新题目的真实 Agent 盲测。应报告独立缺陷命中、误报、复现率和成本，不能只报告用例总数或单因子覆盖比例。
