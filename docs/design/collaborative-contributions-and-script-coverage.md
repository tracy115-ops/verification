# 增量协作与脚本覆盖

## 操作路径

共享项目分为“场景与因子”“补充建议”“用例与脚本”三个工作区。原题、接口说明和项目修订号构成共同基线；主持人托管服务，成员仍使用自己的 Agent。

在“补充建议 → 导入补充建议”展开提示词，将当前设计交给其他 Agent 补漏。返回的增量包包含基线修订号、来源、逐条新增或修改、补充理由。提交后由管理员或评审者逐条比较原内容、建议内容和当前内容，合入或填写理由驳回。高级入口可修改后合入；保留原建议和实际应用版本。相同名称只提示可能重复，不自动删除。

人工可以在原有因子、场景表单中补充，也可以新增或编辑共享用例。用例关联场景、前置条件、步骤、可观察预期、断言和负责人；场景未评审或用例内容不完整时不能确认用例设计。

每次写入都校验项目修订号。建议根据提交时的历史快照保存原条目，合入时再次比较目标内容；无关条目更新不必废弃建议，目标条目变化则阻止合入。修改后使相关评审失效，旧内容保留在服务端快照中，不整体覆盖其他人的工作。

## 覆盖灯的含义

| 状态 | 产生条件 | 不代表什么 |
| --- | --- | --- |
| 未关联脚本 | 没有当前有效的声明或方法映射 | 没有认定该用例已实现 |
| 已声明覆盖 | 勾选并填写脚本位置、方法或核对说明 | 不是程序核验，也不代表执行成功 |
| 方法映射已核对 | 脚本静态解析成功，关联测试方法真实存在 | 不证明断言充分、行为正确或已经执行 |
| 映射／声明已失效 | 用例或相关场景、因子变化，版本不再匹配 | 旧记录不会继续作为当前覆盖 |

共享用例详情可手工勾选“声明此用例已有脚本覆盖”，填写依据后保存。声明记录成员、时间和用例修订号，取消勾选同样进入项目历史。

“关联 Python 脚本”可上传或粘贴 `.py`，点击静态分析，再为用例选择一个或多个测试方法。主持人需安装 Python；服务仅运行固定 AST 解析器，提交的源码作为标准输入数据，**不导入或执行上传的 Python**。检查语法、真实方法、空方法、2,000 行文件 / 200 行函数限制；有并发上限、输出上限和 3 秒超时。

同名脚本的新版本替代旧版本参与当前覆盖，旧原文及 SHA-256 留作历史。修改关联设计会递增用例修订号，原映射与声明保留并标记失效。重新核对后才能关联新版本，旧执行通过状态不会自动沿用。

## 执行证据单独管理

共享服务不执行测试。可导入带运行 ID、执行 ID、脚本 SHA-256、方法结果与证据摘要的脚本包，校验源文件摘要及方法集合。用例只有全部关联方法均有当前结果且通过，才显示“导入结果通过”；失败、跳过、缺失结果分别展示。上传者提供的结果明确标为导入记录，仍需复核来源，不能当作服务端执行认证。

个人工作流的用例详情也显示覆盖灯。Agent 声明的方法在预检前仅算声明；与原生预检的脚本及方法一致才算映射核对。执行状态只使用与该计划摘要相符的本次真实证据。个人手工声明独立记录在版本 1 的追加事件产物中，不修改用例或执行审批。

## 个人 Agent 与共享项目交接

个人“验证资产”或节点产物窗口可导出协作补充包，只包含题目、需求、因子、场景和用例，不携带 Provider、登录凭据或框架配置。共享导入时选择对应接口，生成待评审建议；运行 ID 加入共享条目 ID，避免与其他人的本地编号冲突。补充包不会直接把内容标为已确认。

若个人运行已生成脚本，还可导出独立脚本映射包。它包含脚本源码及方法关联，存在匹配证据时带结果摘要；共享导入仍静态核对，并比较用例定义及版本。共享用例经过人工修订时旧映射会被拒绝，需按当前用例重新核对。

旧项目无需迁移数据库表：项目格式保持 1，新增可选的 `collaboration.version=1` 扩展。旧项目按空扩展读取，首次写入新功能时保存；已有用例或建议后禁止整体替换分析。每个项目仍受体积限制，超限会拒绝保存，不静默裁剪审计记录。
