# 桌面客户端加入协作

## 操作路径

一位成员在「设置 → 局域网协作」启动主机服务。其他成员打开软件的「项目协作」，扫描服务并选择「在本应用中加入」，或手动输入管理员提供的 `http://IPv4:端口` 地址。使用管理员发放的个人令牌登录，然后选择共享项目；浏览器仍可加入同一服务。

主机需要 Node.js 24+；普通桌面成员不需要启动服务或安装 Node.js。主机应用关闭后服务停止，成员可以看到连接失败，服务端项目保留。当前登录方式是个人令牌，不是账号密码注册或企业 SSO。

## 数据与传输

桌面和网页复用 `TeamWorkspace`、权限规则、项目版本、增量贡献、评审及脚本覆盖映射。桌面通过限定用途的 Rust `team_request` 接入现有 HTTP API，网页继续使用同源请求。服务器的 Origin 和角色检查保持不变，也没有放宽 WebView CSP。

原生请求仅接受显式 IPv4／localhost 服务根地址、端口 1024–65535、GET／POST 和列举的协作路由。拒绝 URL 账号、路径、查询、片段、跳转与非单播地址；15 秒超时，最多 8 个并发请求，请求体上限 1 MiB、响应上限 2 MiB。企业内网可能采用非 RFC1918 地址段，因此不根据私有地址段拒绝管理员明确提供的 IPv4。

最后选择的服务地址保存在本机；令牌只保存在按规范化服务地址隔离的 sessionStorage 中。刷新可以恢复当前窗口的身份；更换服务时清除当前服务身份，不向新主机转发旧令牌。Agent 接口指南显示实际协作主机地址，不能把 `tauri.localhost` 作为外部 Agent 的服务地址。

## 协作视图

入口按「连接服务 → 登录身份 → 选择项目」分步进行。项目使用可搜索的列表，不通过长下拉框选择。进入后连接步骤消失，顶部只保留项目身份、成员入口和更换项目；服务地址、退出和更换服务收入「连接与账号」弹窗。

内容按「需求 → 测试因子 → 场景评审 → 用例与脚本 → 补充建议」切换，每次只显示当前步骤，允许多人并行处理和回看。需求页保留原始题目与外部接口，可合入既有设计；场景页提供分工、待评审筛选、逐条讨论和评审，评审角色可筛选已具备评审条件的条目。因子和场景不再同时挤在三列中；因子编辑、场景新增、成员管理均在弹窗中完成。

未保存的场景修改会阻止切换内容步骤、项目或退出当前身份；并发冲突保留草稿。脚本声明、真实方法映射与执行结果仍分别记录，不通过手工操作伪造测试绿灯。

共享服务同步项目设计数据；个人 CLI 会话、Provider 凭据及本地流程运行不会因此自动上传。两个桌面进程的本机验证不代替另一台电脑的防火墙、广播和路由验证。
