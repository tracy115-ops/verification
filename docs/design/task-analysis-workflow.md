# 面向任务的黑盒测试设计

日期：2026-10-28。本文是下一阶段设计，不表示所有功能已实现。参考 [ONES 测试管理](https://ones.cn/products/testcase) 的需求与任务关联、用例组织和测试计划，保留轻量任务视角。

## 从入口到结论

1. 创建项目与验证任务，选择单人或团队，导入题目和框架；固定原文修订、范围与目标。没有源码是正常输入。
2. Agent 按子系统 / 功能 / 接口拆解可验证需求，逐条记录来源片段、输入输出、规则、待澄清问题；用户确认或修改。
3. 对每个需求生成测试因子及水平：输入类型 / 边界、身份、权限、状态、时序、并发、重放和依赖故障等。每条记录注明来源、适用前提、风险、假设与未知点；未写明的规则不能伪造预期。
4. 根据规则建立场景树和因子组合。逐条展示标题、需求、因子水平、前置条件、预期与来源；标注未覆盖、候选、已确认、排除及原因。组合不能简单笛卡尔积：先风险和规则驱动，再按预算补充成对组合和边界，排除不可达组合。
5. 覆盖视图按需求列出因子、场景和缺口，点开回到原文；需求 / 因子变化使相关场景、用例及审批失效。覆盖灯只代表设计评审状态，不代表运行成功。
6. 已确认场景生成逐条用例，展示前置条件、步骤、输入、预期、断言和来源。支持搜索、筛选、批量评审、编辑 / 退回与变更历史；用例量大时分页或虚拟列表，不能在聊天栏堆长文本。
7. 选择可信框架和目标后生成脚本，逐条映射用例到测试方法；预检、执行确认、实际运行和证据收集。执行错误、跳过与业务断言失败分别展示。
8. 报告聚合执行结果、候选问题与证据，可从问题回到用例 → 场景 → 因子 → 需求原文；人工复现后确认，历史执行快照不随新设计改写。

## 信息架构与数据归属

项目下有多个验证任务；任务下保存题目修订、需求、因子 / 水平、场景、用例和多次执行。执行固定当时的输入和审批摘要；可复用用例库属于项目，需要明确引用和版本，不能让一次任务修改所有历史。任务页使用概览、需求、因子、场景、用例、执行 / 问题页签；列表显示 ID、标题、来源、关联、状态与负责人，右侧详情保留原文和编辑 / 评审操作。个人 CLI 会话与团队项目当前是不同存储，尚不能假装关联；应增加显式项目 / 任务 ID 与迁移方案，再做共享和权限。

## 自动发现与可靠性

Agent 输出版本化结构：`Requirement`、`Factor { id, requirementIds, name, levels, source, assumptions }`、`Scenario { factorLevels, requirementIds, expected, source }`、`Case`。系统校验 ID 唯一、引用存在、来源可定位、因子水平属于对应因子、预期有依据；未覆盖需求、无场景的因子水平、无用例的场景逐条列出。Agent 建议标候选，人工接受 / 修改 / 排除；没有量化依据时不宣称覆盖完整。黑盒无源码时不生成实现细节或根因结论。

## 当前差距与实施顺序

个人流程新增因子 / 水平结构、场景引用及来源校验：新生成场景必须带因子与水平，旧运行继续兼容但不会自动补齐。未被任何场景引用的因子水平列为覆盖缺口。团队设计的因子仍未与个人运行关联；因子 / 场景逐条编辑、版本化及变更失效仍待实现。随后打通项目协作和执行追溯，每一步用多任务隔离、缺失 / 冲突需求、边界 / 并发题目和回归执行作验收，不把静态示例当业务资产。
