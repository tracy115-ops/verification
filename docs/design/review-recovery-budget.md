# 人工评审与任务恢复

状态：0.8.1 实现。适用于个人任务的四个确认点，以及插入的人工节点。

## 计时契约

流程总预算限制自动处理时间；人工阅读、讨论和等待确认不应消耗该预算。进入评审时保存 `reviewPausedAt`，确认后把实际等待累计到 `reviewWaitMs`，删除暂停时间。有效截止时间为创建/重试起点 + 配置预算 + 已累计评审等待；暂停期间再排除当前等待。节点调用仍受剩余总预算和自身超时的共同约束。

刷新保留暂停点和等待累计值；不会重复执行已完成节点。取消后显式重试更新预算起点、清除旧等待累计，保留产物和成功步骤。新设计修订建立新的评审暂停点。脚本澄清和引用修复属于显式恢复，重新开始本轮预算。脚本澄清不再限制为两次，仍校验答案、摘要、执行状态及数据容量。

旧版待评审任务没有暂停时间，无法可靠推断此前自动处理耗时。其当前确认点首次批准时重启预算；之后按新规则累计。不会伪造旧暂停时间、修改旧审批时间或自动推进。时钟仍使用本机 UTC 墙钟，本轮没有实现后台调度器或跨机器单调时钟。

新增暂停字段为可选字段，0.8.1 可以读取旧数据。旧版本的严格加载器不能读取含新字段的会话；降级应恢复升级前的数据备份，不能直接让旧客户端写回新记录。

## 并发及版本边界

确认、澄清、排除、脚本修订和引用修复绑定目标会话的任务锁。异步计算前后均检查当前任务版本，版本已变化或会话已删除时拒绝写入；取消确认也不启动后继调用。重试及关闭旧执行同样绑定目标会话，不能误锁当前打开的其他会话。

存储加载和写入检查会话/运行 ID 唯一性，以及运行所属会话。非法导入在覆盖原数据前拒绝。已有执行计划摘要、四次审批和执行端校验继续有效，暂停计时不授予执行权限。

上述版本检查作用于当前应用实例；跨窗口写入一致性仍需要后续事务存储迁移，不能视为多客户端数据库事务。

## 验收

领域测试覆盖四次各等待 48 小时、恢复存储、剩余预算递减、活动时间耗尽、旧任务迁移和取消重试。应用测试覆盖异步确认期间版本更新、删除、取消及会话归属。生产前端交互测试从输入 Spec 开始，三次评审分别等待两天并刷新，完成设计且各 CLI 节点只调用一次；该测试使用离线回复。

真实桌面使用已有 Codex 任务恢复超过 4 小时预算的旧覆盖评审，成功生成新用例并到达用例确认。见[实机验收](../research/reliability-0.8.1-validation.md)。
