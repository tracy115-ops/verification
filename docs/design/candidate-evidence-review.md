# 候选问题证据复核

## 入口与信息顺序

会话及运行记录中的“查看本次报告”共用相同复核组件。候选列表选择问题，右侧默认展示执行证据；窄窗口纵向排列，避免压窄详情。失败摘要优先，完整 traceback 折叠；原始 HTTP 请求响应保持记录顺序。

“用例与原文”显示已批准用例的前置条件、步骤、预期、断言及直接关联需求引用。“执行时脚本”读取匹配执行计划中的脚本和摘要，不能替换为后来编辑的实现。“Agent 分析”保留原始判断，并说明仍需人工复核。报告备注与验证范围独立可见。

## 一致性约束

`candidateTrace` 只接收当前运行上下文。先用报告 `evidenceDigest` 匹配 EvidenceBundle 的 `resultSha256`，再用 `planDigest` 查找 ExecutionPlan，核对 executionId、runId、sessionId。产物包装层的 `digest` 与执行结果摘要不同，不能互换。任一不匹配都不展示替代证据。

测试方法按完全匹配或点分隔的完整后缀匹配请求记录，避免 `test_one_extra` 被误归入 `test_one`。用例 ID 同时属于候选引用和执行计划的脚本映射；只使用 TestCaseSet 与 RequirementBaseline，不采用草稿。缺少关联时显示不完整状态，绝不补写来源或预期。

历史设计修订的查看器传入历史 artifacts 快照；没有运行上下文的旧展示仍可阅读 Agent 说明，但不伪造证据链接。界面只读，不修改历史摘要、判定和批准状态。

## 验证

领域测试使用 0.9.6 真实桌面产物，覆盖正确映射、过期/跨运行引用、方法名误匹配和缺少批准基线。浏览器交互检查 HTTP 详情、原文、脚本、缺失证据、900/1500 像素与深浅主题。原生新版本使用原始 WebView2 用户目录里的真实任务验证；与离线夹具明确区分。
