# 有界交叉分析计划

## 计划与预算

局部设计沿用按 8,000 字节分组的确认需求。设计计划 v2 将每个原跨组检查的左右需求分别按最多四条分块，逐块组合检查，每次最多携带八条完整需求。保留每个原跨组需求配对，调用中仍要求场景引用左右两侧的依据。

任务总数可能增加，单次继续仍受已有批次预算限制。计划最多 600 个任务，超出时返回明确的计划上限错误。剩余关系继续显示，暂停后不会标记为已完成。分块配对无法证明任意高阶组合的覆盖，最终仍需结合源规则与场景评审。

交叉检查使用专用提示词，关注共享状态、身份范围、顺序、重放、资源约束和已声明的并发结果。输入继续包含原文、范围澄清和排除项。场景必须关联两侧需求，因子与状态路径使用准确引用。首步起始状态逐字等于初始状态，后续起始状态逐字承接上一步结果。在公开订单题目第 4 批的相同输入下，请求从 14,083 字节降至 10,629 字节。

## 保存与兼容

checkpoint 保持 version 1，新增可选的 planVersion 2。计划版本进入输入签名，保存前校验每批摘要。导入时核对确认需求、计划总数、局部批次数、缓存索引及状态。

已有旧计划按原顺序恢复。仅在全部局部批次完成且尚无已完成交叉批次时，重试会校验旧签名和全部产物摘要，再迁入 v2 并保留局部产物及索引。已有交叉成果的旧任务继续使用原计划，避免重新解释其索引。

旧版本应用不能读取新增计划字段。升级前保留既有数据保护副本，降级使用升级前的副本，不能将新任务直接导入旧版本。

## 验证

自动化回归覆盖原跨组需求配对保留、每侧四条上限、来源变化与摘要损坏拒绝迁移、旧交叉成果保持原计划、新计划暂停/序列化/恢复，以及只调用剩余检查。真实大题目复测沿用此前保存的两批设计，单次预算为一条细分交叉检查，结果另行归档。
