# 功能与界面验收矩阵

更新：2026-11-06，0.9.7 工作树。每次发布维护本表；“离线界面通过”“实际执行通过”“环境未具备”分别记录，不使用单一的“全部可用”代替。

## 0.9.7 报告证据复核

新增候选列表与执行证据、用例原文、执行时脚本、Agent 分析四个视图。领域检查拒绝过期证据、跨运行计划、方法名误匹配和未批准草稿替代。219 项单元测试、62 项生产界面测试、9 项开发界面测试通过；报告覆盖 900/1500 像素与深浅主题。原生报告复验单独登记在[桌面验收说明](native-desktop-e2e.md)，不把离线历史夹具计为本轮真实推理。

原生首轮发现离线夹具掩盖的摘要语义错误：`VerificationReport.evidenceDigest` 对应执行证据的 `resultSha256`，不是产物包装摘要。修正关联并让夹具中的两类摘要明确不同；领域回归同时检查包装摘要不能用于匹配报告。

## 0.9.6 配置路径复现

读取 0.9.5 桌面当前失败元数据确认：Claude 保存了启动器但未保存独立设置文件；Codex 保存的是模型显示名。设置来源选择现提前到第一步，测试来源可核对。独立浏览器上下文的真实前端集成操作两轮通过：默认来源认证失败 → 选择已有文件 → 保存刷新 → 经真实 Rust 驱动回复；第二轮保留桌面同一启动器，子进程移除临时认证变量。没有修改现有桌面用户存储，也不等同于 Tauri 窗口完整点按。详见[配置不一致复现](../research/desktop-config-mismatch-0.9.6.md)。

## 0.9.6 原生 Release 完整流程补验

后续已通过 WebView2 本机调试通道操作真正 Release 窗口，原 Tauri IPC 未被替换。配置、框架、编排、Spec 输入、4 次评审、脚本生成/预检/执行及报告 13 步完成；4 个用例在缺陷目标 3 通过/1 断言失败，正确参考目标 4 全通过，重复缺陷目标仍稳定复现。原先原生点按未验收项中，**这条 Claude + 本地 Python 完整工作路径现已验收**。系统文件对话框、CodeAgent、SSH/WSL 等边界未扩大。见[原生验收与复验说明](native-desktop-e2e.md)。

## 界面验收

`product-audit.spec.ts` 逐一打开会话、编排、运行、四类资产、协作及七类设置，共 15 个状态。中英文 × 深浅主题 × 900×650/1500×960 共 120 个状态；长页面另拍底部。检查横向溢出、控件越界、无名称按钮线索和未捕获异常，截图供人工复看。几何检查不能代替逐像素、无障碍标准或易用性判断。

`native-surfaces.spec.ts` 另覆盖桌面专属界面的发现、安装探测、托管前后、代理及日志，英文 × 深浅主题 × 两种宽度，共 24 个状态。响应是离线夹具。人工复看发现并修复了窄侧栏会话只剩省略号、弹窗关闭传播、深色小地图/缩放白底及探测状态丢失。

框架、协作补充包和脚本文件控件共享 foundation 样式；巡检对文件按钮、缩放按钮及小地图增加主题断言。`npm.cmd run test:ui:development` 使用独立开发端口重复 120 个主界面状态，输出到独立目录，不覆盖生产截图。

精选截图及结果见[本轮验收](../research/product-audit-0.8.3.md)。尚不能据此声称任意分辨率、系统缩放、全部弹窗组合或第三方桌面主题均已通过。

## 发布门禁

Windows 开发环境运行 `npm.cmd run verify:product`：检查、生产前端、协作、原生工作区、真实 Python 工作流及深层变体依次失败即停止，不调用付费模型。独立真实 CLI、PAC 和公网下载按本表显式执行，不伪装成普通离线测试。

GitHub 打包新增生产界面及协作门禁，并上传截图与失败 trace。安装器仍须通过独立 runner 的安装/升级冒烟测试后发布。0.8.2 的该步骤已确认成功；后续版本按自己的运行结果登记。
