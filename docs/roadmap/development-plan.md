## 本轮验收

1. 默认进入 CLI 会话；常用导航为会话、编排、运行实例、验证资产。底部设置集中管理全局配置。
2. 编排保存后，会话通过选择器或 `/run general-testing Spec内容` 调用保存版本。未保存修改不改变本次调用。
3. 实际推理仅接入复用 CLI 登录的 `native` Profile；保存自定义 Provider 配置不代表已连通。
4. 系统逐节点驱动 CLI，校验 JSON、原文引用与 ID 关系，停在需求、覆盖、用例三个人工确认点。
5. 运行保存定义、Profile、Spec、产物摘要与确认记录；重载不会自动重试模型调用。取消、超时和输出限额有独立处理。
6. 浏览器禁用真实调用与 CLI 检测；桌面通过类型化 IPC 驱动已知 CLI。测试使用离线夹具，不调用付费模型。

## 接下来的开发顺序

先在安装环境验证 CodeAgent，完善框架适配契约，把已验证的“题目 → Python → HTTP 证据”基准接到正式流程节点。随后建设产物编辑 / 退回 / 重新审批、工作流草稿生成和用例库 / 测试计划 / 缺陷闭环；再扩展 Provider 凭据注入、执行隔离、SSH / WSL。企业发布前生成静态 JSON 校验器，收紧 CSP，并加入项目权限与令牌生命周期管理。
