# 首轮开发计划与进度

目标：交付一个可以安装依赖、运行和评审的工作台，先验证编排界面、定义保存与 Agent CLI 接入边界。默认模板统一命名为“测试设计验证流程”，稳定 ID 继续使用 `general-testing`。

## 里程碑

| 阶段 | 实际交付 | 状态 |
| --- | --- | --- |
| S1 工程骨架 | React / TypeScript / Vite、国际化、主题、代码规模检查、领域测试 | 首轮完成 |
| S2 编排工作台 | 预置 13 节点、画布、节点参数、Agent Profile 绑定、定义校验、草稿持久化与导入导出 | 首轮完成 |
| S3 Agent 入口 | 全局 CLI / Provider 元数据配置，Rust 安装与版本探测，Tauri IPC；不在探测时调用模型 | 首轮完成；真实连接未实现 |
| S4 评审工作区 | 示例 Spec / 场景关联、缺口 / 候选 / 确认状态、用例评审入口 | 示例交互完成 |
| S5 后续真实闭环 | 持久化运行状态机、真实 Agent 节点、产物 Schema 与审批失效、用例开发、本地执行 | 待开发 |
| S6 扩展与交付 | SQLite、SSH / WSL、恢复、判定器与有界动作、完整桌面发布验证 | 待开发 |

S1–S4 已完成当前列出的首轮范围；不将编排画布或示例评审等同于已实现自动测试引擎。跨运行审批和证据判定在 S5 开始进入真实闭环。Agent 生成自定义工作流、产物编辑与失效传播随 S5 继续开发。

## 本轮验收

1. 默认进入流程编排，默认模板可选择节点、编辑超时与 Agent 绑定、增加人工复核节点；非法依赖无法保存。
2. 草稿刷新后可恢复，可导出再导入；格式错误的导入不破坏当前草稿。
3. 全局配置存 Profile 元数据与凭据引用，不接受明文 key；节点继承配置或选择具体 Profile。
4. 浏览器预览明确无法访问本机 CLI；桌面通过受限 IPC 只探测预定义 CLI，不开放任意命令执行。
5. 覆盖状态区分缺失、候选、已确认；示例数据明确标识；切换语言不翻译用户原文。
6. 构建、领域测试、国际化 key 与代码规模检查通过；执行可用的 Rust 测试和桌面编译检查，记录限制。

## UI 与调用边界

主导航采用流程模板、运行实例、项目资产、Agent 与 Provider。流程设计页为“节点工具栏 / 编排画布 / 选中节点配置”。节点配置展示角色、CLI Profile、工具权限、超时和输入输出；需求映射、用例评审是节点工作区，阶段条从定义生成。

真实 Agent 接入链为：节点调度 → Agent 服务 → AgentDriver → 已安装 CLI → 归一化事件与产物校验 → 节点状态。当前轮先实现安装 / 版本探测与配置端口，实际推理调度在 S5；测试脚本的本地 / SSH / WSL 执行目标单独配置。

## 实施说明

首轮存储通过可替换 Repository 使用浏览器 / WebView 本地存储；不是最终 SQLite 实现。当前只有保存计数与草稿覆盖，尚无不可变发布历史或运行快照，后续通过接口迁移。实际使用依赖版本由 lockfile 固定。
