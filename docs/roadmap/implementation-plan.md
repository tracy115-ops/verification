# 实施、验证与验收计划

状态：实施建议。阶段按验收能力推进，不以搭建目录或接上聊天界面代表交付。工期在确认测试领域、团队技能和部署形态后估算。

## P0：选型与协议探针

目标：在写大量 UI 前证明本机 CLI 能被可靠驱动。

- 确认桌面 / 团队服务首发形态、第一测试领域和默认模板；建立 ADR。
- 准备无真实凭据的协议 fixture，验证一个 CLI 的版本探测、stdin、结构产物与失败解析；真实调用另做受控冒烟。
- 验证 Windows 入口解析、中文 / 空格目录、取消进程树、超时、两个 Profile 并发与配置不相互污染。
- 建立 Role → Driver → Provider 能力矩阵，显式记录不支持的工具权限与结构输出功能。
- 建立工程骨架及格式 / 类型 / 物理行 / 函数跨度 / i18n key 检查；验证函数 200 行通过、201 行失败，文件 2,000 行通过、2,001 行失败。

出口：至少一个 CLI 在实际机器上产出可校验产物、可取消，且没有改写用户全局配置；确认 Tauri 选择或更新 ADR。不能把本轮 `--help` 探测算作此阶段已完成。

## P1：第一条本地闭环

范围：Markdown Spec、一个 Driver、已有登录、固定内置工作流、需求拆解、场景映射、用例展示 / 编辑 / 确认、一个参考测试框架、本地执行、规则判定与 Markdown 报告。

落实 SQLite revision / 运行快照、不可变产物及最基本审计。此阶段 UI 可用步骤列表，工作流不是任意可编程平台。

出口：登录锁定样例能从原文追到 FAIL 证据；需求从 5 次改 3 次后旧映射和用例显示失效；全跳过、零断言和缺报告不能 PASS。崩溃后恢复不丢失确认与已完成产物。

## P2：CLI / Provider 与可保存工作流

范围：按同一契约接入剩余 Driver（最终 Claude / Codex / Pi）、Provider 向导、Profile 隔离、能力诊断、Agent 生成工作流、草稿保存、发布、复制和导入导出。

补齐类型化编译、未知节点拒绝、无环检查、能力校验、预算与审批摘要。保存定义不会产生进程或网络调用；发布新修订不改变历史 run。

出口：同一业务流程替换 Driver 不改变领域对象；错误协议 / 无效模型可定位；非法环、悬空绑定、类型错配或越权动作无法启动。生成失败仍能保存草稿与诊断。

## P3：模板开发与三类执行目标

范围：用户模板 manifest、参数校验、diff / 冲突处理、SSH、WSL、证据 manifest、远端状态查询、超时取消与资源清理。

出口：用相同已确认用例分别在本地、SSH、WSL 运行并追溯。断线、半传输、缺证据、目标身份变化和取消失败均有可解释状态；未知副作用任务不会重复执行。

## P4：判定闭环与企业交付

范围：多框架解析器、覆盖审查、条件动作、缺陷草稿、补测派生、有限修复提案、诊断导出、保留策略、迁移 / 备份恢复、桌面发布验证。

出口：断言失败不能被分析 Agent 翻成 PASS；原文 / 日志中的诱导指令不能提升动作权限。动作重复投递有去重记录，预算耗尽可停止，修复保留原测试标准。

产品全部目标的本地版验收至少覆盖 P1–P4；P1 仅代表最小闭环。

## P5：按需求建设团队模式

项目级角色权限、凭据分发、集中 Runner、团队模板库、CI 触发、统一审计与中心存储。先证明有这些部署需求再实施；如果首发要求多人协作，应提前调整 P0 架构决策，不能仅把本地 SQLite 放到共享盘。

## 核心验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| Spec 存在未定义边界 | 显示澄清项；不能默默固化 Agent 猜测 |
| 一个必需覆盖义务无场景 | 红灯并列出具体缺口 |
| 候选映射未确认 | 黄灯，不进入正式已确认覆盖分子 |
| 修改需求、用例或脚本 | 受影响审批失效；历史运行快照不变 |
| 用户查看并编辑用例 | 保存新 revision，开发采用新摘要 |
| 模板缺参数或脚本被手改 | 显示参数错误 / 合并冲突，不能覆盖 |
| CLI 退出 0 但输出坏 JSON | 节点失败或有限修正，不能视为成功 |
| stdout 分片 / 重复 / 未知事件 | 解析正确或明确降级；不丢终态、不重复提交 |
| 远程任务启动后断线 | 查询 task ID 对账；不直接重跑 |
| 取消后有存活子进程 | 保留 cancelling / 未确认状态与诊断 |
| 日志缺失或报告未完成 | INCONCLUSIVE / ERROR；不显示全通过 |
| 实际断言 FAIL、Agent 声称 PASS | 确定性结果仍是 FAIL，冲突可见 |
| 所有用例被跳过 | releaseReadiness 为 false |
| 动作被重复派发 | 同一幂等键只产生一项业务动作或明确显示无法确认 |
| 切换中英文 | ID、状态、映射和快照不变，消息 key 完整 |

## 测试分层与目标

领域单测覆盖状态机、追溯计算、变更失效和判定规则；契约测试使用固定 CLI 事件与结果文件；集成测试覆盖事务、迁移、文件 hash 和进程回收；桌面关键路径通过模拟 IPC 的 UI 测试加真实桌面冒烟验收。

不要假定浏览器自动化能直接控制所有 Tauri WebView；P0 核实平台测试能力。真实模型调用不进入普通单测或每次 CI，避免费用、模型漂移和网络造成不稳定；小规模认证记录版本、Provider 和复现输入。

建议初始性能验证集为 1,000 条需求、10,000 条场景、100,000 条用例及 100 MB 日志，目标包括映射索引、列表虚拟化、增量事件与日志背压。性能数值是待测目标：在指定基准机争取原文 / 场景点选 p95 < 300 ms、正常本机取消请求 5 秒内确认；不满足时记录测量和改进，不提前宣称达标。
