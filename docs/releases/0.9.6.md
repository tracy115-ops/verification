# 0.9.6 — 先选配置来源，再测试 Agent

修复“CLI 驱动验证成功，但界面一直认证失败”的引导缺口：来源选择现在是设置第一步，清楚显示已保存的启动文件、配置目录、独立设置文件和模型。Claude 可查找已有设置文件并显式使用；只读元数据，不返回凭据，不自动启用备份。模型值含空格时提示可能填写了显示名。

测试区域可核对本次使用的保存来源，修改后旧验证失效。诊断日志新增是否绑定启动器/目录/文件的布尔标记，不泄露具体路径或配置内容。

真实前端操作经原生审计桥验证了未绑定认证失败、选择文件、保存刷新、真实 CLI 短测试成功；第二轮保留桌面相同启动入口。已安装桌面窗口点按因自动化宿主不可用，仍单独列为未验收。原已保存配置不会被自动替换；升级后需在第一步确认并选用自己的已有配置。

详见[排查证据、复验方式和边界](../research/desktop-config-mismatch-0.9.6.md)。

验证：215 项前端单测、42 项 Agent Rust 测试、61 项生产界面回归、9 项开发版巡检通过；桌面编译、Clippy 及格式检查通过。真实界面集成短测执行两轮，均从认证失败恢复到真实回复；其中一轮显式保留与桌面相同的启动器绑定。付费测试独立 opt-in，未混入普通 CI。
